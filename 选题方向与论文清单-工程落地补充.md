## 四、由工程落地文献看：建议的方向调整

### 4.1 两个推荐的新方向

**新方向 A：养殖数据质量治理（对应 E3，180 篇工程文献支撑）**

- **问题**：现场部署的第一道坎不是模型不够好，而是**数据是脏的**——传感器缺失、漂移、异常、不同设备口径不一致。已有工作大量集中在「用更好的模型预测水质」，却较少见「把不可靠的原始数据变成可用的数据」这一环被系统性地工程化。
- **为什么适合你们**：纯软件、不需要硬件、不需要现场准入（可用公开水质数据平台构造缺失/异常）；又是任何后续系统的前置条件。
- **为什么不是「文献空白」式立论**：本方向文献量很大（本批 180 篇候选筛出 34 篇），**不能说没人做**。正确的立项逻辑是「**能力差异**」——若你们能接入本校或湛江本地的多源实测数据（不同设备、不同频率、有质量问题），就能做别人做不了的真实数据治理评测。

**新方向 B：养殖预警/诊断 AI 的输出可信性工程（对应 E10，含漂移监测与幻觉审计）**

- **问题**：AI 给出的预警与建议一旦发布给养殖户或保险方，**错了要担责**。生产环境的模型漂移监测、输出的事实核查、拒答回退，是落地绕不开的一环。
- **为什么适合你们**：纯软件；且你们上一轮《蓝哨》项目已经积累了一套「逐数字证据审计 + 忠实度指标 + 拒答回退」机制（见其复盘文档第七节「遗留资产」），**这是可以直接接续的真实资产**，不是从零开始。
- **诚实提醒**：该机制在上一轮被判定为「真实但撑不起独立项目」。本次若要做，必须绑定一个具体的、有人真的会看的输出场景（例如对虾病害预警简报），并找到愿意当「评审方」的真实用户或指导老师，否则会重演上一轮的问题。

### 4.2 作为支撑层使用的方向

| 工程方向 | 怎么用 |
|---|---|
| E1 物联网感知与传感网络 | 给 D1/D3/D5 提供**可部署的感知层**设计参考（节点选型、组网、回传） |
| E6 模型轻量化与边缘部署 | 给 D1/D4 提供**端侧落地**技术路线（量化/蒸馏/推理加速） |
| E5 精准投喂装备与机电控制 | 给 D1 补上**「识别→决策→执行」闭环**里被现有竞品留出的执行端 |
| E2 数字孪生与决策支持平台 | 给任何方向提供**系统架构与看板**的实现参考 |
| E8 无人机与遥感 | 给 D3 提供**大范围、低成本的巡检数据获取**手段 |
| E9 水下声学 | 给 D1/D2 提供**浑浊水体下的替代感知通道** |

### 4.3 不建议的方向

- **E4 水下机器人与网箱巡检装备**、**E9 水下声学**：硬件单价常在数万元级，1 万元预算难以覆盖，且队伍无机械/水声背景。
- **E5 精准投喂装备**：若走「造一台投饵机」的路线，需要机械设计与加工能力；建议只做其**控制与决策部分**（软件侧）。
- **E7 溯源与可信数据**：可作为新方向，但离养殖现场远，拿不到真实供应链数据时容易做成纸面系统。

### 4.4 一条必须重复的纪律

本项目上一轮失败的原因，是用「文献空白」立项。本批 300 篇文献**只证明「检索范围内有哪些工作」，不证明「哪些没被做过」**。凡准备写进材料的「未见 / 缺失 / 空白」，必须先做一轮针对性反证检索，并优先查**同城、同场景、官方来源**——像上一轮那样漏掉同城竞品，代价是整道题作废。

## 五、检索方法与可复现说明

### 5.1 流程

1. **初检**：10 个工程方向 × 共 74 条英文检索式（含专门为养殖场景构造的领域化检索式）；每条打两个通道——「2021 年起相关度排序前 100 条」+「2024 年起、检索式后加 `China` 前 60 条」。
2. **去重**：按 DOI 剔除第一批 133 篇；标题归一化后在批内与方向间去重。
3. **相关性门禁**：每方向须同时命中「工程能力词」与「领域词」两组关键词；另设跨领域噪声排除表（作物、畜禽、比特币、智慧城市、脑肿瘤等）。
4. **配额配平**：近三年中国第一作者 → 近三年国内合作 → 近三年国外 → 早期国内 → 早期国外。
5. **落地标记**：按标题特征词给每条打上「工程落地 / 方法分析」标签。

### 5.2 可复现脚本

| 文件 | 作用 |
|---|---|
| `tools/eng_search_cr.py` | 抓取 Crossref（含限流退避与本地缓存 `tools/_cache_cr/`） |
| `tools/eng_select.py` | 按 DOI 与第一批去重 + 门禁 + 配平 + 落地标记 |
| `tools/eng_gen.py` | 生成 `doc/工程落地补充/` 下全部分方向清单、总表、CSV、BibTeX |
| `tools/eng_topic_md.py` | 生成本文件 |

按 `eng_search_cr → eng_select → eng_gen → eng_topic_md` 顺序重跑即可复现。（`tools/eng_search.py` 为 OpenAlex 版本，已写好但因限流未能完成，待其恢复后可用于复检口径。）

### 5.3 局限（必须如实说明）

1. **本批「国内占比」口径弱于第一批。** Crossref 不提供机构国别字段，本批国别由机构名称字符串推断（匹配 china / 省市名 / 常见城市名 / taiwan·hong kong·macao 等标记），且**仅 68.1% 的记录带机构信息**。因此「国内」是**低估**，引用这两个数字时必须同时给出覆盖率。若要严格口径，需在 OpenAlex 解除限流后复检。
2. **中文期刊覆盖有限**：Crossref 对 CNKI / 万方收录不全，本批「国内」文献主要是中国学者发在国际期刊/会议的英文论文；覆盖中文核心期刊须另行检索 CNKI。
3. **工程落地标记是标题启发式**：仅看标题特征词，会漏标也会误标，只能作为**筛选线索**，不能作为结论。
4. **未做引文追踪**：仅主题检索；建议对每个方向前 3 篇高被引综述补「参考文献回溯 + 被引追踪」。
5. **年份以 Crossref 记录为准**：在线优先出版可能造成年份偏差，引用前以 DOI 原文为准。
6. **本清单只提供元数据**，不含论文结论与数字；引用具体结论必须阅读原文。
7. **两批数据源不同**（第一批 OpenAlex、第二批 Crossref），因此两批的「国内占比」**不可直接相比**。
