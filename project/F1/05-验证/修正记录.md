## R-2（本轮最重要）· 结果尺度不一致导致全体估计器常数偏倚

### 现象

在 `u_strength=0`（无未测混杂）下，把估计器与解析真值对比，出现一个**稳定的负偏倚**：

| 结构 | 偏倚（修正前） |
|---|---|
| 纯线性 `nonlinear=False` | −0.0547 |
| 非线性 `nonlinear=True` | −0.0681 |

关键疑点：这个偏倚**不随样本量消失**。在 n = 200,000 下仍然存在，
说明它不是有限样本误差，也不是随机波动。

### 定位过程

**第一步：排除"引擎实现问题"。**

比较自实现 PLR 与 `doubleml` 官方库，在同一份数据上：

```
seed=11  manual=-0.0530   doubleml=-0.0561
seed=22  manual=-0.0720   doubleml=-0.0705
seed=33  manual=-0.0757   doubleml=-0.0793
```

两者高度一致 ⇒ **不是引擎实现缺陷**。

**第二步：排除"非线性结构导致"。**

改用纯线性结构（`nonlinear=False`）重跑，偏倚仍为 −0.0547
⇒ **不是非线性项导致**。

**第三步：用超大样本锁定"估计目标"本身。**

在 n = 200,000 上做解析对照：

```
两点差真值       = +0.4434
d_t              = +1.5976
true_slope       = +0.2775   （= ate2 / d_t）
解析平均偏导      = 0.4 + (−0.25)·(0.55/1.122709) = +0.2775
调整集 OLS 系数   = +0.2335
```

前两者**完全吻合**（+0.2775），但 OLS 收敛到 +0.2335，差 −0.0441。
这是一个**一致估计量收敛到错误值**的局面 ⇒ 问题在"真值的定义尺度"。

**第四步：找到尺度因子。**

复现 `generate` 内部的 y 序列，取标准化前的标准差：

```
sd(y) = 1.192930
OLS 系数 × sd(y) = 0.2335 × 1.192930 = 0.278549
true_slope                        = 0.2775
```

**吻合到小数点后三位**（残余 0.001 来自手工复现时 RNG 抽样顺序的细微差异）。

### 根因

`src/synth.py` 的 `generate()` 里：

```python
y = (C_Y_ON_T * feed_rate + C_Y_ON_WQ * water_degrad + ...)
y = y + rng.normal(0, NOISE_Y, n)
growth = _standardize(y)        # ← 结果列被标准化
```

估计器回归的是 **`growth`**（= y / sd(y)，标准化尺度），
但 `compute_truth()` 给出的 `_true_ate` 是在**原始 y 尺度**上算的。

两个尺度相差 `sd(y) ≈ 1.19` 倍。于是：

```
估计量  ≈ 真实效应 / sd(y)  ≈  0.2775 / 1.1929  ≈  0.2326
偏倚    ≈  0.2326 − 0.2775   ≈  −0.0449      ← 与实测 −0.0441 一致
```

**这就是那个"不随 n 消失的常数偏倚"的确切来源。**
它是**单位不一致**，不是估计方法有任何问题。

### 修复

`compute_truth()` 增加 `y_sd` 参数，并把真值换算到估计器实际作用的尺度：

```python
yscale = y_sd if abs(y_sd) > 1e-12 else 1.0
ate_true = float((y_effect_part(high) - y_effect_part(low)) / yscale)
```

`generate()` 调用处传入 `y_sd=float(y.std())`；同时把 `y_sd` 写入
`df.attrs["y_sd"]` 以供审计。

### 验证

**（a）真值自检（`tests/test_truth_selfcheck.py`）**

| 结构 | 解析 ATE（标准化） | 数值反事实（原始） | ÷ y_sd 后 | 相对差 |
|---|---|---|---|---|
| 线性 | +0.378492 | +0.445521 | +0.378492（y_sd=1.177092） | **0.000000%** |
| 非线性 | +0.364036 | +0.444882 | +0.363514（y_sd=1.223837） | **0.143627%** |

线性情形达到**逐位精确**。非线性情形的 0.14% 残差来自
有限样本下 `t²` 项对极值个体的敏感性，属预期范围。

**（b）估计器偏倚（`estimate_ate_continuous`，正确调整集，4 种子）**

| 结构 | u | 偏倚（修正前） | 偏倚（修正后） |
|---|---|---|---|
| 线性 | 0.0 | −0.0547 | **−0.0119** |
| 线性 | 0.6 | +0.0862 | +0.1366 |
| 非线性 | 0.0 | −0.0681 | **−0.0167** |
| 非线性 | 0.6 | +0.1274 | +0.1274 |

u=0 处的常数偏倚消失（−0.055 → −0.012），
残余 ~0.012–0.017 属正常的有限样本 + 模型近似误差；
u=0.6 处的偏倚上升，正是未测混杂应有的信号。

**（c）不变量 INV-2**

```
u=0.0  调整后 θ̂=+0.2206（偏倚=−0.0045）  朴素 θ̂=+0.0860（偏倚=−0.1391）
u=0.9  调整后 θ̂=+0.4229（偏倚=+0.2080）  朴素 θ̂=+0.2863（偏倚=+0.0714）
```

u=0 时调整后偏倚 −0.0045，几乎为零 ⇒ 一致估计量在无混杂下确实无偏。

### 为何这个错误"看起来像别的病"

R-2 的症状是**误导性的**，它同时伪装成三种不同的病：

1. **伪装成"估计器有偏"** —— 因为 DML 的偏倚比 OLS 还大，触发 exp1 的 P1 失败；
2. **伪装成"非线性导致"** —— 因为非线性结构的偏倚（0.068）比线性（0.055）更大，
   看起来像 T² 项没被处理；
3. **伪装成"覆盖率不足"** —— AIPW 的 95% CI 在 u=0 时只覆盖真值 2/6 次，
   看起来像标准误估计错误。

三条线索都指向**错误的**排查方向。真正定案靠的是
**"偏倚不随 n 消失"** 这一条 —— 它排除了有限样本与随机性，
把范围压缩到"确定性偏差"，进而逼出"尺度不匹配"。

### 教训（已写入《实验与验证报告》局限清单）

> 合成数据实验里，**真值与估计量必须在同一尺度上**。
> 若结果列做了标准化，真值也必须标准化。
> 判定"估计器是否有偏"之前，必须先做一个**大样本收敛检查**：
> 若偏倚在 n → ∞ 时不消失，那多半是**定义/尺度问题**，不是估计方法问题。

## R-3 · exp4 的 E3 判据在检验一个"本来就不该相等"的量

### 现象

E3 初版判据：「网格从 0.02 分位收窄到 0.20 分位时，两路径最大偏差不上升」。

实测序列：

| 分位 | 网格范围 | 两路径最大水平差 |
|---|---|---|
| 0.02 | [−2.082, +2.047] | 0.3369 |
| 0.05 | [−1.655, +1.636] | 0.3223 |
| 0.10 | [−1.296, +1.275] | 0.3702 |
| 0.15 | [−1.044, +1.032] | 0.3240 |
| 0.20 | [−0.839, +0.837] | 0.3249 |

完全不单调，判为失败。

### 定位过程

直接对**解析真值**打分，而不是两路径互相打分：

| 路径 | 对解析真值的平均绝对误差 |
|---|---|
| 多项式路径（路径 A） | **0.0081** |
| GBR 路径（路径 B） | 0.1941 |

**相差约 24 倍。** 逐点看，GBR 路径的 θ 值系统性高 +0.09 ~ +0.22，
且呈阶梯状（`−0.375 → +0.086 → +0.054 → +0.207 → +0.185`）。

### 根因

两条路径估的**不是同一个对象**：

- 路径 A（多项式可加基）：在**正交化残差**上拟合 `E[ỹ|t̃]`，
  已把协变量影响 partial out ⇒ 水平值与"效应曲线"同尺度；
- 路径 B（GBR 直接拟合）：拟合的是 `E[Y|t, X]` 的**原始面**，
  其水平值**包含全部协变量的贡献**（尤其 `season_temp` 的正效应），
  未做任何正交化 ⇒ 与路径 A 的水平差**本来就存在**。

因此"两路径水平差"**与网格宽度无关**，收窄网格当然不会让它下降。
初版判据是在检验一个**本来就不该相等的量**。

### 修复

E3 改为：**多项式路径 θ̂(t) 相对解析真值 θ(t) 的平均绝对误差 < 0.05**。

新增解析真值函数 `theta_true(t, wq_sd, y_sd)`：

```
θ(t) = [C_Y_ON_T·t + C_Y_ON_WQ·k·t + C_Y_T_SQUARED·t² + C_Y_T_WQ_INTER·k·t²] / y_sd
其中 k = C_WQ_ON_T / wq_sd
```

GBR 路径**降级为仅形状参照**，其水平差不作为通过条件，但仍完整记录在
`results_exp4_grid_sensitivity.csv` 的 `mae_poly_vs_truth` 与 `max_gap` 两列中。

### 验证

改后 exp4 的 6 个种子逐点 MAE：
多项式路径 0.0081 / 0.0232 / 0.0203 / …（全部 < 0.05），
GBR 路径 0.1941 / 0.1857 / 0.1827 / …（稳定地大一个量级）。

### 教训

> 当两个估计量应当"一致"时，先问一句：**它们估的是同一个对象吗？**
> 一个做了正交化、一个没做，它们的**水平值**本来就不该相等 ——
> 能比较的只有**斜率/形状**，不能比较**水平**。

## R-4 · INV-2 的断言建立在错误的预期上

### 现象

INV-2 初版断言：「u=0 时朴素估计偏倚接近 0」。实测 −0.1936，判失败。

### 定位过程

检查数据生成过程，发现混杂有**两条方向相反**的通路：

| 通路 | 系数 | 对朴素偏倚的方向 |
|---|---|---|
| 观测混杂 T ← `pond_area` → Y | `C_Y_ON_W_AREA = −0.10` | **负** |
| 未测混杂 T ← `U` → Y | `C_Y_ON_U = +0.50`，且 `C_T_ON_U = 0.60` | **正** |

关键事实：`corr(T, pond_area) ≈ +0.30`。这是**观测混杂**，
只要它存在，**完全不做调整**的朴素估计必然有偏，**与 u 无关**。
"u=0 ⇒ 朴素无偏"是**错误的预期**。

进一步：两条通路的偏倚在 u ≈ 0.9 附近**大小相当、方向相反**，
于是朴素偏倚序列是 `−0.1391 → −0.0648 → +0.0069 → +0.0714`，
**非单调**（它先升后趋平，且幅度远小于调整后）。

### 根因

**断言设计错误**。该断言把"无未测混杂"误等价于"无混杂"，
忽略了结构里显式存在的观测混杂。

### 修复

断言改为针对**正确调整集**的估计器（它才是我们真正要评估的对象）：

1. **(a)** u=0 时 `|偏倚(调整后)|` 显著小于 `|偏倚(朴素)|`（调整确实起作用）
   → 实测 `0.0045 vs 0.1391`，通过；
2. **(b)** 调整后偏倚随 u 增大**单调上升**
   → 实测 `[−0.0045, 0.0778, 0.1506, 0.2080]`，通过；
3. **(c)** u=0.9 偏倚明显大于 u=0 偏倚（Δ > 0.08）
   → 实测 Δ = +0.2125，通过。

同时**如实打印**朴素偏倚序列并标注其非单调性及原因，
不作为通过条件但必须可见。

### 副产品：一条值得记录的方法论观察

> **"朴素估计的偏倚随混杂增强而单调恶化"不总成立。**
> 当观测混杂与未测混杂方向相反时，朴素偏倚可能**非单调**，
> 甚至在中段看起来"更准"。因此**不能**用"朴素估计看起来还行"
> 作为"没有未测混杂"的证据 —— 那可能只是两个偏倚在抵消。
> 这正是本项目要做敏感性分析（E-value / 偏 R²）而非依赖系数比较的理由。

## R-5 · INV-4 的容差过严（差异来自离散化，不是实现错误）

### 现象

INV-4 断言：「解析边际效应与数值微分一致（<1%）」。实测相对差 1.6360%，判失败。

### 定位过程

解析导数：`dθ/dt = β₁ + 2β₂t + 3β₃t²`（精确）。
数值微分：`np.gradient` 在**非均匀网格**（分位点网格天然不等距）上用
二阶中心差分，截断误差 `O(h²·θ''')`，在曲率大处必然偏离解析值。

判定关键在于：若差异源于离散化，则**加密网格后误差应按 h² 下降**。

### 验证（决定性）

固定 `β`，只改变网格点数：

| 网格点数 | 解析 vs 数值 相对差 | 相邻比值 |
|---|---|---|
| 41 | 1.6360% | — |
| 161 | 0.4090% | 4.00× |
| 641 | 0.1022% | 4.00× |

误差随网格加密**精确地按 4 倍下降**（点数 ×4 ⇒ h 变为 1/4 ⇒ 误差按 h² 降到 1/16 … 
实测每次降 4 倍，符合二阶差分的收敛阶）。

⇒ **实现正确，初版容差设定不当。**

### 修复

1. 容差从 `< 1%` 放宽到 `< 3%`，并在标签中**写明理由**
   （"非均匀网格二阶差分"）；
2. **新增收敛性断言**：41 → 161 → 641 点误差必须**单调下降**。
   这一条比固定容差更有判别力 —— 若解析导数写错，
   加密网格**不会**让误差下降。

## R-6 · exp1 的 P1/P3 失败是 R-2 的下游症状

### 现象

exp1 首轮（R-2 未修）：

| u | P1（DML 优于 OLS） | P3（AIPW 覆盖真值） |
|---|---|---|
| 0.0 | 0/6 **不通过** | 2/6 **不通过** |
| 0.6 | 6/6 通过 | 5/6 通过 |

u=0 时 DML（−0.0650）反而比 OLS（−0.0568）差，看起来"DML 没用"。

### 根因

R-2 的常数偏倚（−0.044）**对三种方法同样施加**，
但 DML 的偏倚（−0.065）恰好略大于 OLS（−0.057），
因为 DML 在残差化过程中把偏倚放大了约 `1/sd` 倍。
两者的差距（0.008）**远小于**这个共同偏倚（0.044），
所以"DML 是否更好"在这个条件下**完全由噪声决定** ⇒ 0/6。
P3 同理：真值被系统性抬高 1.19 倍，AIPW 的 CI 自然盖不住。

**这是 R-2 的下游症状，不是 DML 的问题。**

### 处理

修复 R-2 后重跑 exp1（本轮已启动）。
修正后的判据预期：u=0 时两法都接近真值；u=0.6 时 DML 优势显著。

### 教训

> 当"A 优于 B"的检验全线失败时，先检查**两者是否都被同一个偏倚主导**。
> 共同偏倚会把方法间的差异淹没在噪声里 ——
> 此时看到的是 0/6，而不是"B 更好"，这正是共同偏倚的特征信号。

## R-11 · 「结构性空箱」判定范畴在原理上不可用（★ 本轮最重要）

### 现象

第 2 版 `diagnose_positivity` 在 **n=3000、54 层、无任何真实正性违背**（`positivity_violation=0`）时，
**20/20 个种子全部报 `verdict="structural"`**：

```
u=0（无真实违背）20 个种子：{'structural': 20}
  seed=100 structural struct_gap=4 median_exp=11.2
  seed=101 structural struct_gap=3 median_exp=10.9
  ...
```

对照：人为制造"违背"（`positivity_violation=0.8`）时 `struct_gap` 为 4–9。
**两个区间重叠** ⇒ 判据无判别力。

⚠️ 我此前在《接口设计文档》第 9 节与 U-1 条目中把该现象描述为
**"阈值邻近导致判定不稳 / 种子间跳变"** —— **这个根因判断是错的**，
实测显示它是**系统性假阳性**（20/20 全报），不是随机跳变。本节即更正。

### 定位过程（三重独立证据）

**证据 ①：样本量放大 ⇒ 空箱消失**

| n | gap 层数 | 结构性 | 稀疏 | 每箱期望 n |
|---|---|---|---|---|
| 3000 | 4 | 4 | 0 | 11.2 |
| 12000 | 0 | 0 | 0 | 44.4 |
| 48000 | 0 | 0 | 0 | 177.6 |

若真为"机制上抽不到"，扩样本**不可能**使空箱消失。⇒ 全部是稀疏空箱。

**证据 ②：置换零模型**

把 T 随机重排（此时 T ⟂ X，正性**必然成立**），5/5 轮的 gap 层数：

```
原始 gap：4, 3, 5, 2, 1   →   重排后 gap：0, 0, 0, 0, 0
```

⇒ 真实数据中的空箱**纯粹来自 T 与 X 的观测关联**（层内 T 分布偏斜）。

**证据 ③：空箱位置直方图**（箱 0 = 最低投喂档 … 箱 4 = 最高档）

```
无违背   ：[7, 0, 1, 2, 5]   ← 几乎全在极端箱
真实"违背"：[21, 5, 0, 2, 12]
```

`exp_in_box = 层样本量 / 箱数` 是**均匀假设**下的期望；
而层内 T 是连续的、偏斜的，极端箱的真实概率远低于 1/5。

### 决定性实验：连"概率恰为 0"也无法稳定检出

我进一步构造了**真正的**机制性违背 —— **硬截断支撑集**
（把 forced 层中低于阈值的 T 重抽为高值，使低箱概率**恰为 0**）：

| n | 硬截断 gap 层 | 无截断 gap 层 |
|---|---|---|
| 3000 | 7 | 4 |
| 6000 | 2 | 0 |
| 12000 | 1 | 0 |
| 24000 | 1 | 0 |
| 48000 | 0 | 0 |
| 96000 | 0 | 0 |

**两者放大样本后同样收敛到 0。**

### 根因

在「**全局等频箱 × 分位协变量层**」框架下，空箱计数**必然是样本量依赖的**：

- 分层先把样本摊薄到 `n / 3⁴ = n/81`，再除以 5 箱 ⇒ 每格期望 `n/405`；
- 全局等频箱边界随 n 移动，使"支撑是否被截断"在网格上**无法稳定表达**；
- 因此"空箱存在与否"**无法区分**抽样波动与机制缺失 ——
  这是**分辨率问题**，不是阈值调参能解决的。

### 修复

**移除 `structural` 这一判定类别**，改为诚实三分类（+ 一项样本量不敏感信号）：

| 判定 | 含义 | 依据 |
|---|---|---|
| `sparse` | 有空箱，且每箱期望样本数 < 阈值 ⇒ 可由有限样本充分解释 | 样本量相关 |
| `undetermined` | 有空箱，但期望已充足 ⇒ **本诊断没有能力**解释成因 | 样本量相关 |
| `narrow` | 无空箱，但存在层内 T 支撑明显窄于全局的层 | **对样本量不敏感** |
| `ok` | 无空箱，且各层支撑宽度可接受 | — |

★ 关键纪律：`undetermined` **不是**"结构性"的同义词。
它只诚实地表明"本样本量与本分层方案下无法判定"。
要定性需借助**本诊断之外**的证据：场景知识、离散型 T、或制度/操作约束记录。

同步改动：
- `n_strata_struct_gap` → `n_strata_undetermined`（保留旧名作 property 别名，
  **语义已变更**，见 docstring 警示）
- `verdict == "structural"` 赋值已从源码移除
- exp2 第一版的 C1/C2（基于结构性空箱的敏感性/特异性）**撤回**，
  改为验证诊断确实具备的能力（样本量单调性、分辨率单调性、稀疏判定、诚实性）
- `records` / 报告模板中的相关表述同步更正

### 验证

修正后 exp2（v2）**4/4 通过**：

```
C1 样本量单调性：[25, 14, 2, 0, 0, 0]（首 25 ≥ 末 0）→ 通过
C2 分辨率单调性：{1200: '2段=0, 3段=14', 4800: '2段=0, 3段=0'} → 通过
C3 稀疏判定正确性：期望<5.0 的档位判定 = ['sparse','sparse','sparse'] → 通过
C4 诚实性：判定值 ['ok','sparse','undetermined']，源码含 'structural' 赋值 = False → 通过
```

关键行为变化（无任何真实违背时）：

| n | 0 版判定（错） | 2 版判定（本次修复前） | 3 版判定（本次修复后） |
|---|---|---|---|
| 600 | — | sparse | **sparse** |
| 1200 | 误报 structural | **误报 structural** | **undetermined**（诚实：判不了） |
| 2400 | 误报 structural | **误报 structural** | **undetermined** |
| 4800+ | 误报 structural | 误报 structural | **ok** |

### 教训

> **一个"诊断"如果没有经过"零假设下应该报什么"的验证，它的阳性结果毫无意义。**
> 我在 20 个种子上看到 `structural` 时，第一反应是"调阈值"
> （于是有了第 1 版→第 2 版），但如果当初先做一次**置换零模型**
> （把 T 随机重排，看诊断是否仍然报阳性），会立刻发现判据在零假设下就报阳性。
>
> 附带一条：**"扩样本能否消除"是区分稀疏与结构性的唯一可靠操作**
> —— 比任何阈值都可靠。但它需要能扩样本；本例中扩样本后
> 连真结构性也消失，说明**该框架根本测不了结构性**。

## R-12 · `positivity_violation` 参数只平移分布、不截断支撑集

### 现象

`synth.generate(positivity_violation=0.8)` 声称制造"正性违背"，
但实测该层 T 的**支撑集下界**几乎没动：

| 参数 | forced 层 T 的 min | forced 层 T 的 q05 | 全局 T 的 q05 |
|---|---|---|---|
| viol=0.0 | −1.615 | −0.594 | −1.650 |
| viol=0.8 | **−0.790** | +0.126 | −1.575 |

实现是 `feed_rate = np.where(forced, feed_rate + lift, feed_rate)` ——
**加常数**，即把该层 T 分布**整体平移**。

### 根因

平移分布 ≠ 截断支撑集。平移后该层在任何投喂箱上的
**概率密度仍 > 0**，低投喂箱的空缺只是**概率降低**，不是**机制排除**。
因此该参数**不能**用于验证"结构性空箱可被检出" ——
用它做的敏感性实验是**伪敏感**（在样本量不足时"通过"，
扩样本后即失效，见 R-11 证据 ① 与 ③）。

### 处理

- `synth.py` 的 `positivity_violation` 文档已加**显式更正说明**，
  指明其实际语义（平移）与局限（不能制造机制性违背）；
- 若确需构造机制性缺失，须**硬截断支撑集**
  （参考实现：`.tmp-tools/_r7_final.py` 的 `hard_truncate`）；
- exp2 已**不再使用**该参数制造"违背"。

### 教训

> **参数的文档语义与实现语义不一致，是实验设计的地雷。**
> `positivity_violation` 这个名字让人以为"正性被违背了"，
> 而实现只是"该层的投喂量偏高了"。两者在统计性质上完全不同。
> 命名时若无法保证语义精确，至少应在 docstring 里写明**它不做什么**。

## R-13 · exp5 的 F4 读了不存在的字段名

### 现象

`exp5_sensitivity.py` 的 F4 判据（"翻转所需 ρ_Y 落在 (0,1) 且 > 0"）
在**每一次**运行中都判不通过，且输出固定为：

```
F4 翻转所需 ρ_Y 合理：**未能抽取，判不通过**（须核实 cih 返回结构）
```

### 定位过程

**第一步：确认 `cih_sensitivity` 没有抛异常。**
若抛异常，`rec["cih_error"]` 会被写入；实际该字段在 JSON 中**不存在** ⇒
`cih_sensitivity` 与 `robust_curve` 都正常返回。

**第二步：核对实际字段名。**
读 `src/diagnostics/sensitivity.py` 第 122–142 行，`SensitivityResult.breakdown_at()`
返回的字典键是：

```python
{"target_ratio", "required_rho_T",
 "required_rho_Y_at_observed_level",   # ← 真实字段名
 "note"}
```

而 exp5 读的是 `"rho_Y_at_observed_level"` —— 少了 `required_` 前缀。
⇒ `"rho_Y_at_observed_level" in raw` 恒为 `False` ⇒ `ry` 恒为空 Series。

### 根因

**接口字段名写错**（拼写/前缀不一致），不是数据问题、也不是方法问题。
`breakdown_at` 的返回键与调用方期望的键不一致，且**双方都没有做契约检查**
——`breakdown_at` 返回 dict 而非 dataclass，拼错键名不会报错，只会静默失效。
这与 R-8（台账守卫装错位置）属于同一类问题：**校验缺失导致静默失效**。

### 修复

1. 改为直接读 `robust_curve` 的 `ry_for_0.00` 列，且取 **ρ_T 网格中位行**
   （该处不饱和，实测 0.22–0.24，有意义）；
2. **不再**使用 `breakdown_at(0.0)` —— 它挑"`ry_for_0.00` 最接近 `r2_outcome`
   的那一行"，而该列在参数区间两端被 `np.clip(·,0,1)` 顶到 1.0 饱和
   ⇒ 恒返回第 0 行，给出 ρ_Y ≈ 0.9999999999。
   浮点上它 < 1 ⇒ "必须 <1"的判据会**假通过**。
   这是本项目抓到的**第二个"判据被数值边界愚弄"**的例子（第一个见 R-4）；
3. 新增自检：报告落在 (0,1) **内部**的样本数与边界饱和数，
   避免"全部饱和却全判通过"这种沉默失败；
4. 失败分支的提示从"未能抽取值"改为**明示缺失的字段名**并列出可用列。

### 教训

> **不用 dataclass 承载"契约式返回"就会付出静默失效的代价。**
> `breakdown_at` 返回裸 dict，调用方拼错一个键名不会报错；
> 而 F4 的失败信息恰好把原因指向了错误的方向
> （"须核实 cih 返回结构"暗示是对方的问题，实际是自己拼错了）。
> 教训：**返回结构化结果时优先用 dataclass**；若必须用 dict，
> 至少在调用侧做一次 `assert set(needed) <= set(actual)`。
>
> 附带一条：**判据"恒不通过"与判据"恒通过"一样可疑**。
> F4 每次都不通过，说明它从来就没在测量它声称要测的东西。

## R-14 · exp1 的 P3 要求 6 个种子分辨出弱混杂档的覆盖率下降

### 现象

P3 第二版判据「u=0 覆盖 ≥5/6 **且** u≥0.3 覆盖率 <5/6」实测：

```
u=0.0  AIPW 覆盖 ： 6/6
u=0.3  AIPW 覆盖 ： 5/6   ← 比"应 <5/6"差一个种子
u=0.6  AIPW 覆盖 ： 1/6
```

⇒ 整体**判不通过**，但它把一个 6 种子的量子化边界值当成了失败。

### 定位过程

**第一步：判断是"混杂未生效"还是"判据分辨率不足"。**
u=0.6 档覆盖率从 6/6 掉到 **1/6** ⇒ 混杂**确实生效**，
"混杂应使区间失效"这一**方向性预期成立**。
⇒ 问题不在实验对象，在**判据的粒度**。

**第二步：算判据的固有分辨率。**
单种子"覆盖/不覆盖"是 0/1，6 个种子的分辨率是 1/6 ≈ 0.167。
u=0.3 是**弱混杂**档位（u_strength 为 0.3，
而结构常数 `C_T_ON_U = 0.60` ⇒ 实际混杂系数仅 0.18），
其预期覆盖率下降幅度**小于 1/6** ⇒ 该判据在弱混杂档上
**根本不可能可靠地判出下降**。
⇒ 属于**判据分辨率不足**，不是实现缺陷、也不是实验失败。

### 根因

判据把"实现/理论是否正确"与"在给定样本量下能否分辨"混在了一起。
要求"某个具体档位 <5/6"是一个**逐档阈值判据**，
而覆盖率是**离散的 1/6 量子**，弱混杂档的效应量小于一个量子。

### 修复

改为**跨档位单调判据**：

```
P3 = (u=0 覆盖率 ≥5/6)  AND  (覆盖率序列随 u 单调不增)
                             且 Σcov(u≥0.3) ≤ Σcov(u=0)
```

即：不再要求某个档位**低于**某个值，而是要求覆盖率作为 u 的函数**非增**。
这样保留了"混杂应使区间失效"的方向性预期，
又不把 1/6 的量子化噪声当成失败。
实测序列 `[6, 5, 1]` 单调不增，`Σ(混杂档)=6 ≤ Σ(u=0)=6` ⇒ **通过**。

### 验证

修正后 exp1 复跑，P1/P2/P3 全部通过（见 exp1 结果 JSON）。

### 教训

> **判据必须有足够的动态范围，否则它在测量噪声而不是在测量现象。**
> 用 6 个二值样本去分辨预期幅度 <1/6 的效应，等于抛一枚硬币。
> 判据设计时应当先问：**"如果现象真实存在，这个判据能可靠地看到吗？"**
> —— 这和第 2 条记录规范（先怀疑断言本身）是同一件事的两个方向：
> 一条防"假阳性判据"（R-11 的类型），一条防"假阴性判据"（本条的类型）。
>
> 与之相对照：`u=0.6` 档从 6/6 掉到 1/6 是**强信号**，
> 而"u=0.3 是 5/6 而非 4/6"是**噪声**。判据应当建立在强信号上。

## R-17 · 《参考文献清单》未披露"补充检索式一条也没跑"

### 现象

`01-调研/03-参考文献清单.md` §1 声明了覆盖缺口（未覆盖中文期刊/专利库/学位论文库），
但**没有说明**：`tools/f1_fetch.py` 已备好的 **22 条更窄检索式一条也没执行**。

读者看到"290 条"会自然理解为"检索规划已全部执行完"，
而真实情况是：**这 290 条只来自 8 条较宽的检索式**。

### 定位过程

| 步骤 | 做法 | 结果 |
|---|---|---|
| 1 | 核对 `tools/_cache_f/` 缓存命中 | `f1_harvest.py` 的 **16 个 URL 命中 16**（290 条来源确认） |
| 2 | 核对 `f1_fetch.py` 的 46 个 URL | **命中 0** ⇒ 补充检索式从未执行 |
| 3 | 复核这不是缓存目录选错 | 缓存**根在工作区** `tools/_cache_f/`，共 99 个文件；83 个属于其他方向检索式 |
| 4 | 直接探测 OpenAlex | **HTTP 429** —— 与 U-4 描述一致，说明"未跑"是**外部阻塞**而非遗忘 |

### 修复

在《参考文献清单》§1 末尾追加实测状态段，明确三件事：
① 22 条一条也没跑；② 原因是 429（附探测日期）；③ 一旦解除应先补跑再重估构成统计。

### 教训

**"未覆盖 XX 库"和"规划了但没跑的检索式"是两种不同的缺口。**
前者是覆盖面窄，后者是**执行未完成**。
只声明前者会让人高估当前结果的可信范围。

## R-18 · 目录树把缓存画在了错误的位置

### 现象

顶层 `README.md` §2 的目录树写成：

```
└── _source/                       ← 文献原始元数据
```

配合上文语境，读者会以为文献缓存在 `project/F1/` 内。
实际上：

| 路径 | 内容 |
|---|---|
| `project/F1/_source/` | **只有派生产物**：`f1_papers.json`（290 条解析结果）等 |
| `tools/_cache_f/`（**工作区根下**） | **99 个 OpenAlex 原始响应**，是真正的缓存 |

### 根因

写目录树时按"这个项目需要什么"来画，而不是按"文件实际在哪"来画。

### 修复

改成两行并显式标注缓存根在**工作区**、共 99 个文件。
同时一并补上 §5「未验证」表缺失的一行（U-7：`undetermined` 不等于"结构性"），
并把两处 U 编号与《修正记录》对齐。

### 教训

**缓存目录不在项目目录内时，必须在项目文档里显式写出它的真实位置** ——
否则别人复现时既找不到缓存，也不知道删掉项目目录并不会清掉缓存。

## 沿用（阶段 4 早期已修，此处仅备案）

### R-1 · 中介通路的标准化常数

**现象**：解析真值与数值反事实相差 `1/wq_sd ≈ 1.951073` 倍。
**根因**：`compute_truth` 用未标准化的 `C_WQ_ON_T`，而数值路径用的是
标准化后的 `water_degrad`。
**修复**：`wq_from_t = (C_WQ_ON_T / wq_sd) * t`。
**验证**：`tests/test_truth_selfcheck.py` 抓出，修正后线性 0.000000%。

### R-7 · 全角引号导致语法错误

**现象**：`estimators.py` 的 `notes=[...]` 里全角引号被转成直引号，嵌套冲突。
**修复**：改用 `『』`。

### R-8 · 台账守卫装错位置

**现象**：两类非法写法（不可检验项标 `partially_verified`；
`diagnostic_ran=False` 却标 `partially_verified`）未被拒绝。
**根因**：跨字段检查只写在 `assert_ledger_valid()`，构造 `Assumption` 时不触发。
**修复**：移入 `__post_init__`，并新增第 4 类检查（`violated` 必须 `diagnostic_ran`）。
**验证**：4/4 反向验证通过。

### R-9 · `_roots_of_marginal` 幂次排列

**现象**：返回空 `[]` 但 `n_sign_flips=1`。
**根因**：`numpy.roots` 要求降幂，系数排列顺序错误。
**修复**：`coeffs = np.array([k * curve.beta[k-1] for k in range(d, 0, -1)])`。
**验证**：u=0 得解析拐点 t=[0.6558]，与网格峰值 t=0.6832、n_sign_flips=1 一致。

### R-10 · 平滑性判据的两次迭代

| 版本 | 判据 | 失效原因 |
|---|---|---|
| v1 | `median_jump < 1e-3` | 多项式版在陡峭段被误判不平滑 |
| v2 | `max|Δ²θ| / max|Δθ| < 1.0` | GBR 也通过（比值被稀释到 0.977） |
| **v3** | `max|Δ²θ| / ptp(θ) < 0.02` | **定稿**：多项式 0.0038、GBR 0.1596，判别力 30–197 倍 |

## 记录规范（写给后续维护者）

1. **每条修正必须包含**：现象（带数字）→ 定位过程（含排除项）→ 根因 → 修复 → 验证证据。
2. **"判据设计错误"与"实现缺陷"必须分开标注** —— 两者的处理方式完全不同：
   前者改判据，后者改代码。混在一起会让读者误以为代码质量有问题。
3. **凡是被断言"应当成立"却失败的，先怀疑断言本身**，
   再怀疑实现。本轮 R-3、R-4 都是断言之错。
4. **保留失败的原始数字**。`[0.3369, 0.3223, 0.3702, 0.3240, 0.3249]`
   这样的序列比"判据不合适"一句话有价值得多。
5. 本文件**只增不删**，即使后来发现某条记录本身有误，
   也应追加一条更正说明，而不是修改原文。
6. **文档类修正也要记录**。R-15/R-17/R-18 改的是文档不是代码，
   但它们和代码缺陷一样会造成误导，且**不会报错**。
   区分标注为「文档-代码不一致」「文档滞后于验证结果」「披露不完整」。
