## 1. 验证对象与总体思路

### 1.1 这个系统在做什么

F1 做的不是"估一个效应值"，而是**估一个效应值 + 说清这个值的有效边界**：

```
合成/观测数据 ──► ① 角色审计（谁是混杂/中介/碰撞）
                  ② 正性诊断（有没有共同支撑）
                  ③ 估计（DML-PLR / AIPW，双重稳健）
                  ④ 剂量-反应曲线
                  ⑤ 敏感性分析（E-value / 偏 R²）
                  ⑥ 识别假设台账（A1–A6 逐条标注核验状态）
                  ⑦ 报告守卫（不合格输出直接拦截）
```

### 1.2 为什么必须用合成数据

因果推断的**根本困难是无法验证** —— 真实数据里你不知道真值。
所以我们先造一个**真值已知**的世界，用数值反事实算出精确的 ATE，
再看估计器能不能把它估回来。

**这也确定了本项目的边界**：
能验证的是"**方法在该结构下无偏**"，**不能**验证的是"真实养殖系统符合该结构"。
后者需要领域知识 + 真实数据，属 B-1（数据通道）未落实的部分。

### 1.3 合成结构的关键设定

| 变量 | 角色 | 说明 |
|---|---|---|
| `pond_area` / `pond_depth` / `pond_type` / `season_temp` | **协变量 W/S** | 可观测、可调整 |
| `feed_rate` | **干预 T** | 连续，标准化尺度 |
| `water_degrad` | **★ 中介** | 受 T 影响（`C_WQ_ON_T`），又影响 Y（`C_Y_ON_WQ`）。**T→WQ→Y** |
| `fcr` | **★ 碰撞** | 分子含 T、分母含 Y ⇒ 同时依赖 T 与 Y |
| `growth` | **结果 Y** | 标准化后作为估计目标 |
| `shrimp_appetite` | **★ 未测混杂 U** | 仅用于诊断评估，**禁止进入任何调整集** |
| `_true_ate` / `_true_cate` | **真值** | 仅用于评估，**禁止进入模型** |

**三个陷阱**（对应养殖场景的真实结构）：
① 投喂量由水质与虾摄食状态共同决定 ⇒ **内生性**；
② `water_degrad` 是中介，调整它会把直接效应切掉 ⇒ **过度控制**；
③ `fcr` 是碰撞，调整它会制造虚假关联 ⇒ **碰撞偏倚**。

> ⚠️ **结构局限 U-2**：非线性项**不含 T×X 交互** ⇒ CATE 恒为常数，
> **异质性检测能力未被验证**。这是已知缺口，不是通过项。

## 2. 实验 1 · 估计器无偏性验证

**脚本**：`experiments/exp1_estimator_bias.py`
**规模**：n=3000、6 个种子、3 个未测混杂档位（u ∈ {0.0, 0.3, 0.6}）、耗时 567.6 s
**对比方法**：`naive_ols`（不调整）/ `ols_adjusted` / `dml_plr`（自实现）/ `dml_doubleml`（官方库）

### 2.1 跑前写死的标准

| 编号 | 标准 |
|---|---|
| P1 | 在 u≥0.3 的档位上 \|bias(DML)\| < \|bias(OLS)\| 成立 ≥5/6（u=0 不作判定） |
| P2 | DML 偏倚在 6 个种子间的极差 < 0.05 |
| P3 | 覆盖率**单调不增**：u=0 时覆盖真值 ≥5/6，且 Σcov(u≥0.3) ≤ Σcov(u=0) |

> ⚠️ **P3 在 2026-09-20 被第二次修正**（第一次修正见 §2.5 的历史说明，
> 第二次见 §2.6 与 `修正记录.md` R-14）。
> 修正前的判据是「u≥0.3 时覆盖率 **< 5/6**」——
> 它把 6 个二值样本的量子化边界值当成了失败（详见 §2.6）。

### 2.2 结果【合成】【实测】

| 方法 | u=0.0 平均偏倚 | u=0.3 | u=0.6 |
|---|---|---|---|
| `naive_ols` | −0.1356 | −0.0668 | −0.0001 |
| `ols_adjusted` | −0.0037 | +0.0746 | +0.1413 |
| `dml_plr` | **−0.0119** | **+0.0655** | **+0.1306** |
| `dml_doubleml` | −0.0114 | +0.0657 | +0.1351 |

### 2.3 判定

| 编号 | 结果 | 判定 |
|---|---|---|
| P1 | 胜出数 u=0.3: **5/6**；u=0.6: **6/6** | **通过** |
| P2 | 极差 0.0398 / 0.0413 / 0.0375（阈值 0.05） | **通过** |
| P3 | u=0.0: **6/6** ✓；u=0.3: 5/6；u=0.6: 1/6 → 序列 `[6,5,1]` 单调不增，Σ混杂档 6 ≤ Σ无混杂 6 ✓ | **通过**（修正判据后） |

### 2.4 三条值得记录的观察

**观察 1（正面）：u=0 时三者都近无偏。**
`ols_adjusted` −0.0037 / `dml_plr` −0.0119 / `dml_doubleml` −0.0114。
⇒ **无混杂时 DML 并不比 OLS 好**，这是 DML 的正确行为（不是缺陷）。
所以 P1 在 u=0 档**不参与判定** —— 此时三者差异被噪声淹没（首轮曾因此误判为 0/6）。

**观察 2（关键）：u 越大，DML 的相对优势越明显。**

```
u=0.3：OLS 0.0746 vs DML 0.0655  →  DML 好 12%
u=0.6：OLS 0.1413 vs DML 0.1306  →  DML 好 8%
```

⇒ 在**存在未测混杂**时，正交化确实降低了混杂带来的偏倚。

**观察 3（诚实）：朴素 OLS 的偏倚方向会反转。**

```
naive_ols 偏倚序列：−0.1356 → −0.0668 → −0.0001   （单调上升）
```

看起来"朴素 OLS 在 u=0.6 时最准"，**这是个陷阱**：
`naive_ols` 有**两个偏倚源方向相反** ——
观测混杂 `corr(T, pond_area) ≈ +0.30`、`C_Y_ON_W_AREA = −0.10` 带来**负**偏倚；
未测混杂 `C_Y_ON_U = +0.50` 带来**正**偏倚。两者在 u≈0.6 附近**恰好抵消**。

**这意味着**：不能拿"某档位朴素 OLS 很准"当作"不需要调整"的证据。
抵消是巧合，改一个结构常数就反转。

### 2.5 P3 的两次修正史（保留，不掩盖）

P3 是本实验中**唯一一个被改了两次**的判据。两次的性质完全不同：

| 版本 | 判据 | 实测 | 失败性质 |
|---|---|---|---|
| v1 | AIPW 覆盖真值 ≥5/6 | u=0: 6/6 ✓；u=0.6: **1/6** ✗ | **判据自相矛盾** |
| v2 | 双向：u=0 ≥5/6；u≥0.3 **<5/6** | u=0.3: **5/6** ✗（差一个种子） | **判据分辨率不足** |
| v3 | 单调不增（本文现行） | 序列 `[6,5,1]` ✓ | — |

**v1 的错在哪**：u=0.6 时**确实存在**未测混杂，估计量**本应**有偏，
其 CI 因此**理应盖不住真值**。要求它"覆盖 ≥5/6"等于要求混杂不存在
—— 这与实验目的（展示混杂后果）**自相矛盾**。
⇒ v2 改为双向判据，方向是对的。

### 2.6 为什么 v2 仍然要改（★ 判据分辨率问题）

v2 要求 u≥0.3 时覆盖率 **<5/6**，实测 u=0.3 恰好为 **5/6** ⇒ 整体判不通过。

**第一步：确认混杂是否生效。**
u=0.6 档覆盖率从 6/6 掉到 **1/6** ⇒ 混杂**确实生效**，
"混杂应使区间失效"这一**方向性预期成立**。
⇒ 问题不在实验对象，在**判据的粒度**。

**第二步：算判据的固有分辨率。**
单种子"覆盖/不覆盖"是 0/1，**6 个种子的分辨率是 1/6 ≈ 0.167**。
而 u=0.3 是**弱混杂**档（`u_strength=0.3` × `C_T_ON_U=0.60` ⇒ 实际混杂系数仅 0.18），
其预期覆盖率下降幅度**小于 1/6** ⇒ 该判据在弱混杂档上
**根本不可能可靠地判出下降**。

**⇒ 属于"判据分辨率不足"，不是实现缺陷、也不是实验失败。**
登记为 `修正记录.md` 的 **R-14**。

**v3 的修正方向**：改为**跨档位单调判据** ——
不再要求某个档位低于某值，而是要求覆盖率作为 u 的函数非增。
保留了方向性预期，又不把 1/6 的量子化噪声当失败。

> **反面参照**：同一份数据里，`u=0.6` 从 6/6 掉到 1/6 是**强信号**，
> 而"u=0.3 是 5/6 而非 4/6"是**噪声**。
> **判据应当建立在强信号上。**

## 3. 实验 2 · 正性诊断的**能力边界**验证

> ⚠️ **本实验在 2026-09-20 被整体重写**（第一版的判据已撤回）。
> 撤回理由见第 3.1 节 —— 这是本项目**自我证伪**的关键一环。

**脚本**：`experiments/exp2_positivity.py`（v2）

### 3.1 第一版为什么被撤回

第一版设了两条判据：
- C1（敏感性）：`positivity_violation ≥ 0.4` 时结构性空箱层数 > 0；
- C2（特异性）：无违背且 n≥4800 时结构性空箱层数 = 0。

**这两条都被本项目自己的后续验证推翻了**（《修正记录》R-11、R-12）：

| 证据 | 结果 |
|---|---|
| 样本量放大（无任何违背） | n=3000 → 4 个 gap 层；**n=12000 → 0**；n=48000 → 0 |
| 置换零模型（T 随机重排，正性**必然成立**） | 5/5 轮 gap 层从 4/3/5/2/1 **全部降到 0** |
| 空箱位置直方图 | 几乎全在**极端箱**（箱0: 7 个 / 箱4: 5 个），中间箱仅 1–2 |
| 人为**硬截断支撑集**（低箱概率**恰为 0**） | n=48000 时 gap 层**同样降到 0** |

⇒ 在「全局等频箱 × 分位协变量层」框架下，**空箱计数无法区分抽样波动与机制缺失**。
第一版 C1 之所以"通过"，只是因为 n=6000 下样本量仍不足 ——
那是**伪敏感**，不是敏感性。

**因此第 2 版把 `structural` 判定类别从代码中删除。**

### 3.2 新版判据（跑前写死）

| 编号 | 标准 |
|---|---|
| C1 | 无真实违背时，空箱层数随 n 增大**不增**（600→19200 六档，首档 ≥ 末档） |
| C2 | 固定 n、无真实违背时，分层 3 段 → 2 段后空箱层数**下降** |
| C3 | 每箱期望样本数 < 阈值的档位，判定须为 `sparse` |
| C4 | 判定值 ∈ {ok, sparse, narrow, undetermined}，且**源码不含** `structural` 赋值 |

|---|---|---|---|

以换取诚实性。

### 3.5 现行判定的语义（报告必须照此表述）

| 判定 | 含义 | 对报告的要求 |
|---|---|---|
| `sparse` | 有空箱，且每箱期望样本数不足 ⇒ 可由**有限样本**充分解释 | 写"本样本量下细分层导致部分组合无观测"，**不得**写"正性假设被违背" |
| `undetermined` | 有空箱，但期望已充足 ⇒ **本诊断判不了** | 列为**待查事项**；**不得**据以断言反事实不可识别 |
| `narrow` | 无空箱，但存在层内 T 支撑明显窄于全局的层（**唯一对样本量不敏感**的信号） | 提示外推风险，做剔除后复算 |
| `ok` | 无空箱，且支撑宽度可接受 | **不等于**正性成立，只表示本诊断分辨率下未发现违背 |

| D2 | \|Δθ(fcr)\| ≥ 2 × \|Δθ(water_degrad)\| |

### 4.3 动态对照：效应估计【合成】【实测】

### 4.6 三条结论

1. **碰撞的破坏力约为中介的 4.5 倍**（4.02–5.12）。

2. **中介的位移随混杂增强而衰减**（45.33% → 26.37%），

3. **两者同加的位移大于仅加碰撞**（D3 100% 成立），
   说明失调是**可加的**，不存在"加了更坏的变量反而抵消"的普遍规律。

### 5.4 F4 的修正过程（★ 判据"恒不通过"也是一个警报）

**F4 曾经在每一次运行中都判不通过**，且失败信息固定为
"未能从 CIH 结果中抽取值（须核实 cih 返回结构）"。

**第一步：排除"对方模块报错"。**
若 `cih_sensitivity` 抛异常，`rec["cih_error"]` 会被写入；
实际该字段在 JSON 中**不存在** ⇒ 模块正常返回。

**第二步：核对字段名。**
读 `src/diagnostics/sensitivity.py` 第 122–142 行，
`breakdown_at()` 返回的键是 **`required_rho_Y_at_observed_level`**；
而 exp5 读的是 **`rho_Y_at_observed_level`** —— **少了 `required_` 前缀**。
⇒ `"rho_Y_at_observed_level" in raw` 恒为 `False` ⇒ `ry` 恒为空 Series。
**根因是接口字段名写错**，不是数据问题、不是方法问题。
登记为 `修正记录.md` 的 **R-13**。

**第三步：连"改对字段名"都还不够。**
即使字段名对了，`breakdown_at(0.0)` 也会给出**错误的**答案：
它挑"`ry_for_0.00` 最接近 `r2_outcome` 的那一行"，
而该列在参数区间两端被 `np.clip(·, 0, 1)` **顶到 1.0 饱和** ⇒ 恒返回第 0 行。
本次复跑的实测对照行已经证明了这一点：

```
F4 翻转所需 ρ_Y 合理：范围 [0.219, 0.242]（内部 6/6，饱和 0 个）→ 通过
   [对照] breakdown_at(0.0) 返回 [1.000000, 1.000000] —— 被 clip 顶到 1.0 饱和
```

首轮它返回 `0.9999999999925` —— 浮点上 **< 1**，
"必须 <1"的判据因此**假通过**（比"不通过"更危险）。
这是本项目抓到的**第二个"判据被数值边界愚弄"**的例子
（第一个是 R-4 的 u=0 退化比较）。

**最终修复**：读 `robust_curve` **中位行**的 `ry_for_0.00`（实测 0.219–0.242，
全部落在 (0,1) 内部，无饱和），并把 `breakdown_at` 的值另存为对照列；
同时新增"内部样本数 / 饱和数"自检，防止"全部饱和却全判通过"的沉默失败。

**结果 JSON 中的两个字段（保留对照，可审计）**：

| 字段 | seed=11 取值 | 说明 |
|---|---|---|
| `rho_Y_required_to_zero` | **0.24227222830591708** | ★ 判据实际使用的值（`ry_for_0.00` 中位行） |
| `rho_Y_from_breakdown_at` | 0.9999999999925502 | 弃用的饱和访问器，**保留作反面对照** |
| `breakdown_at_saturated` | `true` | 明确标注该对照值已饱和 |
| `rho_T_at_mid` | 0.19067796610169493 | 中位行的 ρ_T（说明取值位置） |

**为什么要把错的那个也留下来**：它是**判据会被数值边界愚弄**的实证。
删掉它，后来者可能重新引入同一个访问器。

> **教训**：**"恒不通过"与"恒通过"一样可疑。**
> 我们习惯警惕假阳性，却容易把"每次都失败"当作"实验不成功"而接受它 ——
> 而一个从不通过的判据，很可能根本没在测量它声称要测的东西。
> F4 的失败信息甚至把原因指向了错误的方向（暗示是对方模块的问题，
