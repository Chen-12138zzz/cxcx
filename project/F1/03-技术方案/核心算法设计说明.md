## 0. 设计总纲：为什么是本项目而不是"跑一遍 DML"

因果推断的标准工具链（DML / DR / TMLE）是**通用**的，跑通它没有任何贡献。
本项目的算法设计围绕一个**养殖观测数据特有的困难**展开：

> **在养殖观测数据上，标准因果估计方法的三个核心假设会被系统性破坏，
> 而破坏的方式不产生任何报错。**

这三个假设是：

| 假设 | 通用表述 | 在养殖观测数据上的破坏方式 | 后果 |
|---|---|---|---|
| **无未测混杂**（unconfoundedness） | 给定协变量后，干预分配与潜在结果独立 | 投喂量由**现场观察**决定（看虾的摄食反应调投喂），而"虾的状态"是影响结果的共同原因，且**只被部分记录** | 估计有偏，但数值看起来完全正常 |
| **正性/重叠**（positivity） | 每个协变量层都有非零的干预概率 | 投喂量在**某些水质/季节下根本不会取某些值**（低温时不可能高投喂），导致这些层的反事实无法推断 | 逆概率权重爆炸，估计方差巨大甚至无意义 |
| **一致性/SUTVA** | 一个个体的结果不依赖他人的干预 | 换水是**村内共用取水口**，一塘换水影响邻塘水质；饲料批次在塘间共享 | 个体干预效应与群体干预效应不等价 |

**因此本项目的算法核心不是估计器本身（那是成熟组件），而是围绕估计器的三件事：**

1. **识别假设的显式化**（Assumption Ledger）：把每条假设写成可检查的条目，而不是写在论文里的一句话
2. **假设违背的量化诊断**（Diagnostics）：正性诊断、坏控制检查、未测混杂敏感性分析
3. **结论的脆弱性报告**（Fragility Report）：输出"要多强的未测混杂才能推翻这个结论"

## 1. 问题形式化

### 1.1 符号

| 符号 | 含义 |
|---|---|
| $i = 1, \dots, n$ | 观测单元（一个塘·一个养殖周期） |
| $T_i$ | **干预变量**（本项目的候选：日均投喂量 / 放养密度 / 日换水率 / 增氧时长） |
| $Y_i$ | **结果变量**（生长指标：SGR、FCR、成活率、单位产量） |
| $X_i$ | **协变量**（水质、气温、苗种来源、塘型、养殖周期长度） |
| $W_i$ | **预处理协变量**子集（放苗前确定：塘面积、水深、塘型、苗种批次） |
| $Z_i$ | **时变协变量**（养殖过程中的水质与环境，**可能是混杂也可能是中介——本项目必须区分**） |

### 1.2 估计目标（Estimand）——必须先声明

本项目**不**默认估 ATE。养殖场景下更有意义的是三个量：

| 目标 | 符号 | 养殖场景下的含义 | 用途 |
|---|---|---|---|
| **ATE**（平均处理效应） | $E[Y(1) - Y(0)]$ | 平均而言，投喂量提高一档对生长的效应 | 与元分析外部对标 |
| **CATE**（条件平均处理效应） | $\tau(x) = E[Y(1)-Y(0) \mid X=x]$ | 效应在什么塘型/密度/季节上更大 | **回答"该不该一刀切"** |
| **连续干预的剂量-反应曲线** | $\mu(t) = E[Y(t)]$ | 投喂量从 t 到 t+Δ 的边际效应 | 受控实验只给 2–3 档，曲线是观测数据的独有价值 |

> **纪律 K-3**：以上三者**均不构成管理建议**。任何文档中出现"因此应投喂 X"即违反红线。

### 1.3 因果图的先验（**必须由评审方确认，不得本项目自行认定**）

养殖场景的**候选**结构（`[待评审方确认]`）：

```
        塘型/面积 ─────────────────┐
             │                     │
             ▼                     ▼
      [季节/气温] ──► 水质(DO,氨氮) ──► 生长/成活 (Y)
             │           ▲  │
             │           │  │
             ▼           │  ▼
         投喂量 (T) ─────┘  残饵/有机物
             ▲                 │
             │                 │
         虾的摄食状态 ◄─────────┘
         (部分未观测)  ← ★ 这是未测混杂的来源
```

**本项目必须显式回答的三个结构问题**（答不出就不做）：

| # | 问题 | 为什么关键 |
|---|---|---|
| Q1 | 「虾的摄食状态」在数据里**被记录到什么程度**？ | 若完全未记录 → 未测混杂严重，只能做敏感性分析；若部分记录（如摄食时长）→ 可作代理变量，但需说明测量误差 |
| Q2 | 水质指标是**混杂**还是**中介**？ | 若是中介（T → 水质 → Y），调整它会**屏蔽掉部分因果效应**（over-control）；若是混杂（水质 → T 且 水质 → Y），不调整会有偏。**两者只能靠领域知识判断** |
| Q3 | 「饲料转化率 FCR」能否进入调整集？ | **不能**。FCR 是投喂量与生长的**下游结果**（坏控制）。调整它会引入碰撞偏倚 |

> **Q2 与 Q3 是本项目最核心的领域判断，也是最容易被做错的地方。**
> 本项目把这两个问题写成**必须由评审方逐条签字确认**的检查项（见 4.2）。

## 2. 估计器设计

### 2.1 主估计器：DML（Double/Debiased Machine Learning）

**为什么选 DML 而不是直接回归**：DML 用正交化（Neyman 正交）与交叉拟合（cross-fitting），
在 nuisance 函数用机器学习估计时仍能得到 $\sqrt{n}$ 一致且渐近正态的估计。
直接回归在存在非线性与高维协变量时会因正则化偏倚而不一致。

```
输入：Y, T, X (协变量), W (预处理协变量)
输出：τ̂ (ATE 估计) + 标准误 + 置信区间

1. 交叉拟合（K 折，默认 K=5）：
   for k in 1..K:
     a. 在训练折上拟合 ── 结果模型  l_0(X) = E[Y | X]
     b. 在训练折上拟合 ── 干预模型  m_0(X) = E[T | X]
     c. 在留出折上预测，得残差：
          Ỹ = Y - l̂_0(X)
          T̃ = T - m̂_0(X)
2. 在全部残差上做部分线性回归：
     Ỹ = τ · T̃ + ε     （用 T̃ 做工具，得到正交得分）
   → τ̂ = argmin Σ (Ỹ - τ T̃)²
3. 方差估计：τ̂ 的渐近方差用正交得分估计
```

**养殖场景的参数选择**（不得照抄默认值）：

| 组件 | 通用默认 | 本项目选择 | 理由 |
|---|---|---|---|
| nuisance 学习器 | 随机森林 / Lasso | 随机森林 + **显式声明它是"预测器"而非"因果模型"** | 养殖数据 n 小、非线性强 |
| 交叉拟合折数 K | 2–5 | **5**（若 n ≥ 100）；n < 100 时降为 3 并报告方差损失 | 小样本下 K 太大反而方差高 |
| 干预变量类型 | — | 连续干预用部分线性 DML；**二值化后另做一版作对照** | 二值化会损失信息但便于与元分析对标 |

> **必须有对照**：连续干预与二值化两版结果**同时报告**。
> 若两者差异巨大，说明估计对干预的编码方式敏感 → 写入脆弱性报告。

### 2.2 异质性效应：因果森林 / DR-Learner

**用途**：回答"效应在什么塘型/规模上更大"（估计目标 CATE）。

```
输入：Y, T, X
输出：τ̂(x) 在每个观测点上的条件效应 + 变量重要性

1. 用 2.1 的交叉拟合残差 Ỹ, T̃ 构造"伪结果"
2. 在 (X, 伪结果) 上训练因果森林（honest splitting）
3. 输出：CATE 预测、变量重要性（哪些协变量调节效应最强）
4. 校准检查：分组（如按塘面积中位数二分）后的组内均值效应
   → 与直接分组估计的结果比对，偏离过大即预警
```

### 2.3 剂量-反应曲线（连续干预）

**用途**：受控实验只给 2–3 个处理档，曲线是观测数据的独有价值。

**方法**：用 DML 的干预残差 + 局部线性回归，或用 DR-Learner 的连续版本，
在干预值的分位数网格上估计 $E[Y(t)]$。

> **纪律**：曲线**只在正性成立的支持域内报告**。超出支持域的部分必须裁掉并标注
> `[超出支持域，不作报告]`。这是本项目与"画一条看起来很漂亮的曲线"的分界线。

## 3. 诊断模块（**本项目的核心贡献**）

### 3.1 诊断一：正性 / 重叠诊断

**问题**：低温季节不可能出现高投喂量 → 这些协变量层的反事实无法推断。

```
输入：干预模型 m̂_0(X)（倾向得分或条件密度）
输出：正性违背报告

1. 对二值化干预：计算 ê(X) = P(T=1|X)
   - 报告 ê 的分布（min, p1, p5, p50, p95, p99, max）
   - 标记 ê < 0.05 或 ê > 0.95 的观测数，报告占比
2. 对连续干预：检查条件密度的支持
   - 在干预值的每个分位点上，报告对应的 X 分布范围
   - 标记"某些 T 值只出现在特定 X 区间"的情况
3. 稳健性对照：
   - 全样本估计 vs 裁掉极端权重样本后的估计
   - 若两者差异 > 阈值 → 写入脆弱性报告
```

**输出格式（示例）**：

| 项 | 值 | 判定 |
|---|---|---|
| ê 的 5% 分位 | 【由代码产出】 | < 0.05 则标记 |
| ê < 0.05 的观测占比 | 【由代码产出】 | > 10% 则预警 |
| 截尾后估计变化 | 【由代码产出】 | > 20% 则写入脆弱性报告 |

> ⚠️ **无数据不产数**：上表在 `05-验证/results_*.json` 产出前**不得填写任何数字**。

### 3.2 诊断二：坏控制检查（**本项目特有，通用工具没有**）

**问题**：调整变量的选择错误（把中介或碰撞放进调整集）会引入新偏倚，且**不报错**。

```
输入：候选调整变量集 A，干预 T，结果 Y
输出：每个变量的角色判定

对 A 中每个变量 a：
1. 时序检查：a 是在 T 之前确定的吗？
   - 是 → 候选预处理协变量（安全）
   - 否 → 可能是中介或碰撞（危险）
2. 中介检查：T 是否显著影响 a？（回归 a ~ T + W）
   - 是，且 a 影响 Y → a 是中介。放进调整集会屏蔽部分效应
3. 碰撞检查：a 是否由 T 与 Y 的共同下游产生？
   - 例如 FCR = 饲料量/增重，同时依赖 T 与 Y → 碰撞
4. 输出角色标签：{预处理协变量, 混杂, 中介, 碰撞, 无法判定}
5. 对"中介"与"碰撞"给出警告，并做"含/不含该变量"的对照估计
```

**输出格式（示例）**：

| 变量 | 时序 | 是否被 T 影响 | 判定角色 | 建议 | 含/不含对 τ̂ 的影响 |
|---|---|---|---|---|---|
| 塘面积 | 预处理 | 否 | 预处理协变量 | 保留 | 【由代码产出】 |
| 溶解氧 | 时变 | 是 | **中介候选** | **必须做对照** | 【由代码产出】 |
| FCR | 时变 | 是 | **碰撞** | **禁止进入调整集** | 【由代码产出】 |

> **这一模块是本项目相对通用因果工具的核心增量**：
> `DoubleML` / `EconML` 不做变量角色判定，它们假定你给的调整集是对的。
> 在水产场景下，"调整集对不对"正是最需要帮助的地方。

### 3.3 诊断三：未测混杂敏感性分析

**问题**：投喂量的决定依赖"虾的摄食状态"，而这个变量可能只被部分记录。

```
输入：τ̂ 及其标准误，以及观测到的混杂强度（作为参照）
输出：推翻结论所需的未测混杂强度

方法 A：偏 R² 型（Cinelli-Hazlett 风格）
  定义：
    R²_{Y~U|T,X}  = 未测混杂对结果 Y 的解释力度（控制 T,X 后）
    R²_{T~U|X}    = 未测混杂对干预 T 的解释力度
  计算"稳健性阈值"：使 τ̂ 的置信区间包含 0 所需的 (R²_Y, R²_T) 组合
  → 与已观测协变量达到的 R² 对比：若阈值低于已观测协变量的解释力，
     说明"一个和已观测变量一样强的未测混杂就能推翻结论"

方法 B：E-value 型（若干预与结果均为连续，用推广版本）
  报告：需要多大的关联强度（风险比尺度）才能把效应解释掉
```

**输出格式**：

| 项 | 值 | 解读 |
|---|---|---|
| 已观测协变量对 Y 的偏 R² | 【由代码产出】 | — |
| 已观测协变量对 T 的偏 R² | 【由代码产出】 | — |
| 推翻结论所需的未测混杂偏 R² | 【由代码产出】 | 低于上两行 → 结论脆弱 |

> **这是本项目最需要忠实执行的一步**：多数应用论文止于报告 τ̂ 与 p 值，
> 本项目的交付必须包含"这个 τ̂ 有多容易被推翻"。

## 4. 识别假设台账（Assumption Ledger）

### 4.1 格式

每条假设必须写成**可检查**的条目，而不是一段叙述：

| # | 假设 | 通用表述 | **养殖场景的具体含义** | **检查方式** | **违背后的影响** | 评审方确认 |
|---|---|---|---|---|---|---|
| A1 | 无未测混杂 | $Y(t) \perp T \mid X, W$ | 影响投喂量决策的所有变量（尤其虾的摄食状态）都已被记录 | 敏感性分析（3.3）+ 领域审查 | 估计有偏，方向取决于混杂结构 | 【待填】 |
| A2 | 正性 | $0 < P(T=t \mid X) < 1$ | 任何水质/季节条件下，各档投喂量都有非零出现概率 | 3.1 正性诊断 | 反事实不可推断，方差爆炸 | 【待填】 |
| A3 | 一致性 | $Y_i = Y_i(T_i)$ | 一个个体的生长只依赖自己的投喂量，不受邻塘影响 | 领域判断：是否存在共用取水口？饲料是否跨塘共享？ | 个体效应 ≠ 群体效应 | 【待填】 |
| A4 | 无坏控制 | 调整集只含预处理或真混杂 | 调整集中不含 FCR 等下游结果 | 3.2 坏控制检查 | 引入碰撞偏倚 | 【待填】 |
| A5 | 稳定单元 | SUTVA 的稳定性 | 干预的定义在塘之间一致（"每天投喂 30 kg"在各塘含义相同） | 数据字典检查 | 干预变量含义不一致 | 【待填】 |
| A6 | 测量无系统性误差 | 变量测量无偏 | 投喂记录是否**按实际投喂量**还是**按计划量**记录？ | **数据字典检查（最关键）** | 干预变量本身有误差 → 衰减偏倚 | 【待填】 |

> **A6 是本项目最需要警惕的一条**：如果养殖记录中的投喂量是"计划投喂量"而非"实际投喂量"，
> 那么它作为干预变量就有测量误差，会产生**向零衰减的偏倚**——
> 即"看起来投喂量没什么效应"，而真相可能是效应被测量误差吃掉了。
> **这条假设不成立，整个方向的结论都不可信。**

### 4.2 评审方确认的强制环节

以下三项**必须**由持有水产/统计背景的人逐条确认，**不得由本项目自行认定**：

| # | 待确认项 | 为什么不能自己定 |
|---|---|---|
| Q1 | 水质指标是混杂还是中介（见 1.3 Q2） | 需要领域知识；判错则调整集错，结论错 |
| Q2 | 调整变量集中是否有坏控制（见 1.3 Q3） | 同上 |
| Q3 | A6：投喂记录是实际值还是计划值 | 只能从数据来源方获知 |

> **这三项未确认前，本项目不得对外报告任何效应估计数值。**

## 5. 方法无偏性验证（合成数据实验）

**为什么需要**：真实数据上没有真值，无法判断估计流程是否正确。
**做法**：构造**已知因果结构**的合成数据，验证估计流程能否恢复真值。

### 5.1 合成数据生成器设计

```
已知结构（显式写死，作为"真值"）：

W  ~ 预处理协变量：塘面积、水深、塘型（离散）
S  ~ 季节/气温（与 W 相关）
U  ~ 未测混杂：虾的摄食状态（★ 可控开关）
T  = f(W, S, U) + noise         ← 干预由协变量 + 未测混杂共同决定（内生）
WQ = g(W, S, T) + noise         ← 水质同时受 T 影响（→ 中介）
Y  = h(W, S, T, WQ, U) + noise  ← 结果

真值：ATE = E[Y(1) - Y(0)]（解析可算）
     CATE(x) = E[Y(1)-Y(0) | X=x]（解析可算）
```

### 5.2 验证矩阵（**每个格子都要跑**）

| 变量 | 水平 | 验证什么 |
|---|---|---|
| 未测混杂强度 $U$ 的影响 | 无（U 不影响 T）/ 弱 / 强 | 估计偏倚是否随 U 增强而单调增大（**这是最关键的验证**） |
| 干预-结果关系 | 线性 / 非线性 / 有阈值 | DML 相比线性回归的优势是否显现 |
| 样本量 | n = 100 / 300 / 1000 | 小样本下交叉拟合的方差代价 |
| 正性违背 | 无 / 中等（部分层 ê<0.05）/ 严重 | 正性诊断能否**发现**问题（诊断的召回率） |
| 调整集 | 正确 / 含中介 / 含碰撞 / 缺失真混杂 | 坏控制检查能否**发现**问题 |

### 5.3 出口指标

| 指标 | 定义 | 通过标准（**须在实现前定死，防止事后调节**） |
|---|---|---|
| **偏倚** | $\hat\tau - \tau_{true}$ | 无未测混杂时 \|偏倚\| 相对真值 < 10% |
| **覆盖率** | 95% CI 覆盖真值的比例（重复 200 次） | ≥ 90%（名义 95%，允许小样本损失） |
| **正性诊断召回率** | 存在正性违背时，诊断报告能标出的比例 | ≥ 80% |
| **坏控制诊断召回率** | 调整集含中介/碰撞时，诊断能标出的比例 | ≥ 80% |

> ⚠️ **通过标准必须在跑实验之前写进 `05-验证/实验与验证报告.md`**，
> 不得在看到结果之后再定。否则"验证"退化为对已有结果的合理化。
