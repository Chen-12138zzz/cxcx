## 1. 系统定位与边界

### 1.1 这个系统是什么

一套**因果推断的估计与审计工具链**，输入是养殖观测数据表，输出是：

1. **效应估计**（含口径标记、标准误、置信区间）；
2. **诊断报告**（正性、坏控制、未测混杂敏感性）；
3. **识别假设台账**（A1–A6，逐条标注证据等级与状态）；
4. **报告守卫记录**（哪些输出因不满足前提而被拦截）。

### 1.2 这个系统不是什么（边界，必须显式声明）

| 不做 | 原因 |
|---|---|
| **不产生预警** | 预警属 E10 方向的范围；本项目只在既有数据上做效应估计 |
| **不给养殖管理建议** | 红线 K-3；观测数据效应估计误用为投喂建议的风险极高 |
| **不做因果发现** | 红线 K-4；生态时序数据的 DAG 假设不可验证 |
| **不做数据质量治理** | 属 E3 方向；本项目假设输入数据的"对错"由别处负责 |
| **不涉及硬件** | 约束 U-4；且同城学生队已占位 |
| **不声称有真实塘口数据** | 约束 U-1；主结果来自合成数据，须标【合成】 |

### 1.3 与相邻方向的分工

```
E3 数据质量治理 ──► 【F1 因果有效性审计】 ──► E10 输出可信性工程
（输入数据对不对）    （从对的数据能否推出因果结论）   （输出结论可信吗）
```

F1 处在**中间层**：上游输入经验证的数据，下游输出待审计的结论。
F1 自己既不验证数据质量，也不审结论的可信性 —— 只审**因果识别是否成立**。

## 3. 关键设计决策

### 3.1 为什么真值要"双重可算"

**决策**：同时提供解析真值（`compute_truth`）与数值反事实（`test_truth_selfcheck.py`
里的 `counterfactual_truth`），两者**互相验证**。

**理由**：本项目在实现过程中**确实两次把真值算错**：

| 编号 | 错误 | 后果 | 如何发现 |
|---|---|---|---|
| R-1 | 中介通路漏 `1/wq_sd` | 真值差 1.95 倍 | 数值反事实与解析式不符 |
| R-2 | 真值未换算到 Y 的标准化尺度 | 全体估计器出现 −0.044 常数偏倚 | 大样本不收敛检查 |

若只有一条路径，这两个错误都会**静默通过**，并污染其后所有实验结论。

**代价**：需要维护两套公式，且必须保证两者的标准化常数一致（这是 R-1 的教训）。

### 3.2 为什么口径要成为显式字段

**决策**：`CausalEstimate.contrast_kind ∈ {"slope", "two-point"}`。

**理由**：这两种口径**不可直接比较**，但实现中极易混淆。
本项目曾因此误判"DML 有 bug"，实际是两个量：

```
two_point = slope × d_t         （d_t = treat_high_mean − treat_low_mean）
```

把它变成**显式字段**后，任何跨口径比较都必须显式调用
`rescale_to_twopoint(d_t)`，从而在代码层面防止误用。

**代价**：`rescale_to_twopoint` 仅在效应近似线性时有效，须在文档中标注。

### 3.3 为什么台账不允许 `verified`

**决策**：`VALID_STATUS = {unverified, partially_verified, violated, not_applicable}`，
**刻意不含 `verified`**。

**理由**：识别假设的核心（A1 无未测混杂）**原则上不可被数据证实**。
允许写 `verified` 会诱导作者给出虚假的确定性，而这些假设恰恰是
审稿人最先质疑的地方。

**配套守卫**（在 `Assumption.__post_init__` 中强制）：

| 规则 | 理由 |
|---|---|
| 不可检验项不得标 `partially_verified` | `untestable` 与"部分验证"矛盾 |
| 标 `partially_verified` 或 `violated` 必须 `diagnostic_ran=True` | 不允许"声称验证过但没跑诊断" |
| 编号不得重复 | 集合级检查 |

### 3.4 正性诊断为什么**不再**声称能区分两种空箱（★ 第三版决策）

**决策**：`verdict ∈ {ok, sparse, narrow, undetermined}`。
`structural` 这一类别**已从代码中删除**。

**理由（实测推翻初版设计）**：

初版设想区分两类空箱 —— 稀疏（期望不足，加样本可解）与
结构性（机制所致，加样本不可解）。但本项目自己的验证证明，
在「全局等频箱 × 分位协变量层」框架下**这个区分做不到**：

| n | 无任何违背时 gap 层 | 人为硬截断支撑集后 gap 层 |
|---|---|---|
| 3000 | 4 | 7 |
| 12000 | **0** | 1 |
| 48000 | **0** | **0** |

两者放大样本后**同样收敛到 0** ⇒ 空箱计数无法区分抽样波动与机制缺失
（每格期望被 `n/(3⁴×5) = n/405` 限死）。证据全文见《修正记录》R-11，
含置换零模型（T 随机重排后 5/5 轮空箱归零）与空箱位置直方图。

**修正后的语义**：

| 判定 | 成因 | 加样本能否解决 | 报告中的处理 |
|---|---|---|---|
| `sparse` | 期望样本数不足 | **能** | 声明"本样本量下细分层致部分组合无观测" |
| `undetermined` | 期望充足却仍空 | **未知** | ★ **不得**断言机制性；列为待查项 |
| `narrow` | 层内 T 支撑偏窄（样本量不敏感） | 否 | 提示外推风险，做剔除后复算 |

**实现教训（两层）**：
① 初版判据用"层样本量 ≥ 阈值"，`n=1200`、`54` 层时每层仅 22 样本却装 5 箱，
   于是**无真实违背也报违背** → 改为"该箱期望样本数"判据；
② 但第 2 版判据**仍然**在 20/20 个种子上误报 `structural` ——
   根因不是阈值调参问题，而是**该框架原理上测不了结构性**。
   真正的教训是：**先做零假设验证（置换重排）再相信阳性结果**。

### 3.5 为什么报告要有守卫

**决策**：`ReportGuard` 在输出前检查，不合格则**拦截或抛异常**。

| 守卫 | 触发条件 | 行为 |
|---|---|---|
| 剂量-反应不平滑 | `is_smooth == False` | **拒绝**输出边际效应 |
| 无 E-value 可算 | 输入不足 | **抛异常**，不留空、不填 0 |
| 缺数据的指标 | 该项未计算 | 输出 `"—"` |

**理由**：报告里一个"看起来合理"的假数字，比一个显式的空缺危险得多。
把守卫**放在输出层**，而不是依赖作者自觉。

## 4. 接口契约

### 4.1 数据表契约（`synth.generate` 的输出）

| 列名 | 角色 | 说明 |
|---|---|---|
| `pond_area` | 预处理协变量 | 塘面积（标准化） |
| `pond_depth` | 预处理协变量 | 水深（标准化） |
| `pond_type` | 预处理协变量 | 0=土塘，1=高位池/铺膜 |
| `season_temp` | 协变量 | 气温（标准化，与塘型弱相关） |
| `feed_rate` | **干预 T**（连续） | 投喂量（标准化） |
| `feed_high` | **干预 T**（二值） | 按中位数切 |
| `water_degrad` | **中介** | 水质退化指数（受 T 影响，影响 Y） |
| `fcr` | **碰撞** | 饲料系数（同时依赖 T 与 Y） |
| `growth` | **结果 Y** | 生长表现（标准化） |
| `shrimp_appetite` | **未测混杂 U** | 摄食状态；**不得进入任何调整集** |
| `_true_ate` / `_true_cate` | 真值 | **不得进入任何模型**（仅评估用） |

**`df.attrs` 契约**（审计必需）：

| 键 | 含义 |
|---|---|
| `cut` | 二值化切点 |
| `treat_high_mean` / `treat_low_mean` | 高/低组的 T 均值（用于口径换算 `d_t`） |
| `wq_mu` / `wq_sd` | WQ 的标准化常数（真值计算必须共用） |
| **`y_sd`** | Y 的标准化常数（★ 真值换算必需，R-2 的修复产物） |
| `nonlinear` / `u_strength` / `positivity_violation` / `n` / `seed` | 数据生成参数（可复现性与审计） |

### 4.2 估计器契约

所有估计器返回 `CausalEstimate`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `point` / `se` | float | 点估计与标准误 |
| `ci_low` / `ci_high` | float \| None | 95% 置信区间 |
| **`contrast_kind`** | str | `"slope"` 或 `"two-point"` |
| `t_ref` / `t_at` | float \| None | two-point 口径的两个取值 |
| `method` / `notes` | str / list | 方法名与备注 |
| `assumptions` | list | 该估计所依赖的假设编号（默认 A1–A6） |

**方法**：`rescale_to_twopoint(d_t)` —— slope → two-point 换算（仅效应近线性时有效）。

### 4.3 禁止事项（接口级）

| 禁止 | 检查点 |
|---|---|
| 把 `fcr` 放进 `covariates` | `audit_adjustment_set()` 报违规 |
| 把 `water_degrad` 放进 `covariates` | 同上（若目标是**总效应**） |
| 把 `shrimp_appetite` 放进 `covariates` | `KNOWN_ROLES` 标为 `unmeasured_confounder` |
| 把 `_true_ate` / `_true_cate` 放进模型 | 代码审查 + 真值列前缀 `_` 约定 |

### 6.1 三层测试

### 6.2 五项不变量

| 编号 | 断言 | 为什么它是"不变量" |
|---|---|---|
| **INV-1** | 同 seed 两次生成逐位相同；不同 seed 不同 | "结果可复现"若不能验证就是空话 |
| **INV-2** | 调整后估计偏倚随 `u_strength` **单调上升** | 混杂的定义决定的 |
| **INV-3** | 碰撞入调整集必然造成显著位移 | 后门通路被打开是数学必然 |
| **INV-4** | 多项式路径判平滑、GBR 判不平滑；解析微分与数值微分收敛一致 | 判据若无判别力则形同虚设 |
| **INV-5** | 非法台账写法必须被拒绝 | 守卫若拦不住非法输入则无意义 |

**INV-2 的修正记录**：初版断言"u=0 ⇒ 朴素无偏"是**错的** ——
数据里存在观测混杂（`corr(T, pond_area) ≈ +0.30`），
不做调整必然有偏，与 u 无关。改为对**正确调整集**的估计器断言。
副产品观察：朴素偏倚**非单调**（观测混杂负偏倚与未测混杂正偏倚相互抵消），
见 `05-验证/修正记录.md` R-4。

**INV-4 的修正记录**：初版容差 `< 1%` 过严，实测 1.64% 判失败。
经收敛性检验（41→161→641 点，误差 `1.636% → 0.409% → 0.102%`，每次降 4 倍）
确认差异来自**非均匀网格的二阶差分截断误差**，非实现错误。
故放宽到 `< 3%` 并**新增收敛性断言**（加密网格误差须单调下降），
后者比固定容差更有判别力。

### 6.3 反向验证（必须做）

不是只验证"正确的东西能通过"，还要验证"**错误的东西不能通过**"：

| 反向用例 | 期望 |
