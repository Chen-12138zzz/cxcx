## ① 用户意图对齐

**原始需求（逐字）**：
> "再写一份详细的PPT，介绍我们产品的功能，服务谁，有什么优势，解决了什么问题，还有为什么我们选择这个命题"

需求可拆为 **5 问 + 1 个形容词（"详细"）**。

**澄清结论（经 AskUserQuestion 一轮确认，用户已明确选定）**：

| 维度 | 用户选定 |
|---|---|
| 产品定位 | **可复现的空间适宜性审计工具链** |
| 服务对象 | 研究者 / 期刊审稿与项目评审 / 下游数据使用者 / 方法接手人 |
| 现状口径 | **工具已完成交付 + 落地计划**（可写"已交付、已跑通"，不写客户/收入/部署） |

**为什么必须先问这两个问题**：F4 与 F1 有一个根本差别 ——
F4 的红线 **G-1 禁止产出任何选址结论或选址图**。
若把"产品"理解成"给养殖户做选址决策"，全篇会与项目自身约束冲突。
用户选定后，落点清晰：**产品是审计工具链，服务的是"需要追问结论适用范围"的人**。

**核心目标**：讲完后希望听众相信四件事 ——
① 这是一个**有边界的产品**，不是"用 GIS 做养殖"；
② 有人真的需要它，而它的差异是**结构性的**（粒度与动机），不是"别人没想到"；
③ 它的能力有**已跑通的证据**（140 断言 + 31 判据 + 五道门禁 exit=0），不是概念稿；
④ 我们**清楚它现在缺什么**（14 条局限），以及为什么这些边界不可绕过。

**"详细"的落地方式**：**14 页**，且**五问各占一整节** —— 不合并、不压缩。
用户点名的问题必须能被**单独翻到**。

**视觉调性**：学术严谨 / 蓝白克制 / 诚实留痕。与 F1 那份**共用同一套设计系统**。

**内容边界**：
- **必讲**：产品是什么、给谁、差异化、解决什么问题、为什么选这个命题、缺什么。
- **不讲**：算法公式推导、代码细节、成员分工（`【待填】` 未落实）。
- **禁碰（下列均为禁用表述）**：任何"已落地/已服务/已收入"式声称；任何"国内首个/首创/空白"式表述；
  任何地块适宜性判断或选址建议；任何 `【待填】` 字段的编造填充。

## ③ 页面大纲

### P1 · 封面（hero）
- 左侧深蓝块：`不产选址图 / 不产选址结论 / 只审计产图这件事与它的适用范围`
  —— 与 F1 那份的"不做预测/不做控制/只检查…"同构。
- 右侧：英文小标 + 主标题「空间适宜性 / 审计工具链」+ 一句话定位。
- 视觉锚点：三个诊断模块 → 汇成「每条结论都带口径与适用范围」。

### P2 · 目录
- 5 章，**逐字与 5 个扉页一致**（契约见 §②）。
- 每章一句副题，说明该章回答什么。

### P3 · 01 这是什么产品（章节扉页）
- Lead：它不是又一个选址系统，也不产出任何选址结论。
  它把**产图这件事本身**拆开，算出每一步选择各自带来多大后果。
- 三条要点：形态 / 交付 / **不做**（用红点区分"不做"）。

### P4 · 产品做哪三件事
- 三张卡（均标「已交付」）：**尺度失配诊断 / 融合账本与误差三分解 / 缺失到可计算后果**。
- 右侧：审计链路 SVG（输入 → 逐项拆开单项扰动 → 输出）+ 交付物卡。
- 副标题即本页立场：**三件事都在"算后果"，不在"算适宜性"**。

### P5 · 产品形态与交付物（peak）
- 形态声明条：**只依赖 numpy · 无网络请求 · 可完全离线运行**，
  并说明**为什么不调 GIS 库**（黑箱无法在"权重变化 0.01"粒度上测量）。
- 四个度量：`3,010` 代码行 / `25` 公开接口 / `140+31` 断言与判据 / `5/5` 门禁。
- 交付物单条清单：审计报告 · 修正记录 26 条 · 原始结果 JSON 4 份 · 一键复现入口。

### P6 · 02 服务谁（章节扉页）
- Lead：不说"面向养殖行业"。四类对象的共同点是——都需要知道结论的**适用范围**。
- 第三条要点用红点：**以下都是目标对象，不是客户名单**。

### P7 · 四类目标对象，四类具体问题
- 2×2 卡：研究者 / 评审 / 下游使用者 / 方法接手人。
- 每卡写「问题」与「拿到什么」。
- 页脚：以上都是目标对象，不是客户名单；本项目未接受任何委托。

### P8 · 03 优势在哪（章节扉页）
- Lead：**不把 WLC 和 AHP 说成创新** —— 那是 2000 年以来标准配方。
  优势来自我们站在什么位置、以及把什么当成了产品能力。

### P9 · 优势不在算法，在两个「不匹配」（hero）
- 左：**粒度不匹配**（海湾级 30 m–1 km vs 池体 50 m；做海湾选址动机上不需要解决）
  与**动机不匹配**（反演精度 vs 决策可审计性；高分辨率 ≠ 高精度）。
- 右：粒度差距的**几何换算 SVG**（1 km 每格约 278 口池；100 m 约 2.78 口；200 m 约 11.11 口）
  + **第二重优势：可分解性**。

### P10 · 04 解决什么问题（章节扉页）
- Lead：三个问题都来自已有文献指出、但尚未被转成数字的缺口；
  每个答案都带**样本量、方法名与适用范围**。
- 三条要点分别对应三个问题。

### P11 · 三个问题，和我们的答案
- 三张横卡，每卡 = 问题 / 答案 / **数字栏**。
  1. 融合换来多少精度 → 取决于用哪个量衡量 → `未标定误差 +0.0488` / `判别力 →0.9961` / `标定后 −0.3271`
  2. 网格粗于池体时 → 决策相对损失 > 信息相对损失 → `比值 2.291（50 m）` / `12/12 种子` / `适用 ≤4 倍`
  3. 少写一项的后果 → 后果与缺失计数不成比例 → `重分类 489/1124` / `权重 131.5/1124` / `计数比 1.85 → 后果 3.7`
- 页脚：**样本 11,236 池体像元（2,809 口池）；方法：尺度失配曲线 · 融合账本 · 缺失到后果映射；全部【合成】**

### P12 · 05 为什么选这个命题（章节扉页）
- Lead：**不以"没人做过"立项**。恰恰相反 —— 这个领域很成熟，
  两篇关键文献都已**公开承认**我们关注的那些缺口。
- 第三条要点用红点：**明确排除：不是"他们没想到"**。

### P13 · 立项逻辑，与我们坦诚的边界（hero）
- 左：三条立项逻辑（依据 8 条全部方法缺口型、空白型 0% / 两篇原文通读 / 差异是结构性的）。
- 右：**组织级反证已显式排除**（同源挑战赛 169 个模型失败，但它证伪的是"能否算得准"，
  本工具不承诺任何反演精度）+ **坦诚的边界 4 条**。
- 页脚标注：该竞赛数据为**二手转述，标【待核实】**。

### P14 · 收尾
- 左侧深蓝块「三句话」（与 P1 的深蓝块呼应，形成首尾结构）。
- 右侧「边界声明」5 条 + **金句条**：
  「判据失败时，先问'是不是我问错了量'，而不是先改判据」。
