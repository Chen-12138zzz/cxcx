# E3 · 门禁 B：能力差异检验

> 审查日期：2026-09-20 ｜ 前置：门禁 A（**已通过**）

---

## 1. 三问自检

### 问一：我具备什么别人不具备的能力？

| 候选能力 | 是否成立 | 依据 |
|---|---|---|
| 有养殖塘真实脏数据 | **不成立** | 无现场准入；仅有公开**环境**地表水数据 |
| 有数据质量算法能力 | **成立，但无差异** | SaQC / pyhydroqc / Great Expectations 已成熟 |
| **有「物理先验约束嵌入」的设计能力** | **成立** | 《蓝哨》的**物理自洽合成数据生成器**正是这类能力，且已交付过 |
| 有可信性工程资产 | **成立** | 与 E10 同源，可互补（E3 治输入，E10 治输出） |
| 能做可复现 benchmark | **成立** | 这是 E3 最有分量的候选能力 |

**问一结论**：E3 的**核心能力是「把养殖物理先验嵌入数据质量判定，并产出可复现 benchmark」**。
这个能力确实有别于通用 QC 工具（它们无养殖语义），也与 SaQC 的纯统计路线不同。

### 问二：为什么具备这些能力的人没做？

| 能力的持有者 | 为什么没做 |
|---|---|
| KISTERS WISKI / HydroCorrect | 面向**水务局与环保机构**，市场不包含养殖；做养殖语义不划算 |
| SaQC / pyhydroqc | **通用环境工具**，设计目标就是领域无关；加养殖语义会削弱通用性 |
| 养殖平台（Manolin/渔鱼/广为海洋） | **把它当子模块消化了**——对它们而言这不是卖点，做了也不宣传 |
| 高校环境/水务团队 | 有方法但**没有养殖场景的问题意识**，不知道「生物污损致漂移」是什么 |

**关键判断**：这一问的答案是**「粒度不匹配 + 付费意愿弱」**，而不是「他们做不了」。
**粒度不匹配是真实且不会自动消失的**——WISKI 不会为了对虾塘去做养殖语义，
因为那要改产品定位，收益却很小。

**但必须承认**：这类空隙**脆弱**。任何一支有养殖数据的水产院校团队，只要想做就能做。
E3 的优势窗口比 E10 更窄。

### 问三：不具备这些能力的人做得了吗？

**部分做得了**：
- 通用 QC 流程——任何人都能用 SaQC 跑；
- **但「养殖物理先验」需要领域理解**——例如溶氧的昼夜节律、
  投喂后 2 小时的浊度尖峰不应判为异常、生物污损使传感器读数**缓慢单调漂移**（易误判为真实趋势）。

**这是 E3 唯一真正的门槛，也是它必须写进申报书的立论点。**

## 2. 阻断项

| # | 阻断项 | 状态 |
|---|---|---|
| B-1 | 可用数据（养殖塘真实数据 vs 公开环境水质） | **未落实**；需明确降级方案并如实标注 |
| B-2 | 能否产出可复现 benchmark 并公开 | 未落实（**这是 E3 的核心交付物**） |
| B-3 | 无水产专业成员，物理先验来源需外部审阅 | 未解决 |

---

## 3. 门禁 B 结论

| 项 | 结论 |
|---|---|
| 三问是否都能正面回答 | **是**（问一有真实候选；问二为粒度不匹配；问三部分成立并给出具体门槛） |
| 是否存在阻断项 | **是，三条**，但均可通过降级方案部分解决 |
| **门禁 B 判定** | **条件性通过** |
| 完成日期 | 2026-09-20 |

**注意 E3 与 E10 的区别**：
- E10 的门禁 B **完全通过**，但卡在外部阻断项（B-1 评审方）；
- E3 的门禁 B **条件性通过**，其脆弱点是「空隙随时可被填补」；
- **两者互补**：E3 治输入可信，E10 治输出可信，组合起来是一条完整主线。
