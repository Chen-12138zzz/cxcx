## 这是什么

一个**软件层**，不产生预警，只在预警产生之后回答四个问题：

1. 这条建议依据的数字从哪来？
2. 模型有多确定？
3. 不确定时是否该拒答？
4. 误判了谁负责？

它面向湛江**散户 / 小棚高位池**场景，覆盖对虾投喂、病害、缺氧三类预警文本。

## 目录约定

```

├── README.md                     ← 本文件

├── _source/                      ← 中间产物（JSON、脚本），非交付物
├── 00-项目管理/                  ← 唯一事实来源、进度与门禁
├── 01-调研/                      ← 前缀强制顺序：01 竞品 → 02 问题 → 03 文献
├── 02-申报材料/                  ← 申报书、立项论证
├── 03-技术方案/                  ← 设计说明书、算法说明、接口文档
├── 04-原型系统/                  ← 源代码 + 测试 + 实验脚本
├── 05-验证/                      ← 验证报告 + 结果原始数据
├── 06-成果/                      ← 论文、软著、PPT、源代码清单、截图
├── 07-结题/                      ← 中期检查、结题报告
└── 08-复盘/                      ← 复盘报告
```

**约定**：
- `01-调研/` 的文件名前缀**强制**顺序，顺序本身就是门禁的执行方式。
- `05-验证/` 的原始数据**保留不清理**——它是数字可追溯的基础。
- 临时文件集中放 `_source/` 或 `.tmp-tools/`，不污染交付目录。
- 文件名不使用空格与特殊字符。

---

## 三条最重要的纪律

1. **不得用「文献空白」立项。** 本项目走**能力差异型**论证。
2. **「未见披露 ≠ 不存在」。** 所有否定性结论必须给出举证范围与日期。
3. **未做的不得写成已做。** 约束要如实写进《能力与约束》，不得包装成创新。
