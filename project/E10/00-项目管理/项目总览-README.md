## 2. 立项依据

### 2.1 一句话立论

> **本项目做「养殖预警文本的事实核查与问责留痕」软件层。它不产生预警，
> 只回答：这条建议依据的数字从哪来？模型有多确定？不确定时是否该拒答？误判了谁负责？**

### 2.2 依据的性质说明（三问，必须回答）

| 问 | 回答 |
|---|---|
| 这是**能力差异型**依据还是**空白型**依据？ | **能力差异型。** 核心能力＝可复用的可信性工程资产（逐数字证据审计、跨域压力测试台、物理自洽合成数据生成器）+ 主流评测工具的低成本复现路径 |
| **空白型依据占比**是多少？ | **0%**。本项目的全部论证不建立于"无人做"。16 方向 99 条竞品显示所有方向均已落地 |
| 是否声明了「未见披露 ≠ 不存在」？ | **是**，见《01-竞品与近邻尽调》第 0 节与第 2.4 节 |

### 2.3 差异化落点

> **差异化的落点是「场景化问责」，而不是「做可信性」。**

| 对比对象 | 它做的是 | 本项目做的是 |
|---|---|---|
| 西北农林「稷安智算」 | **安全合规层**输出可信（防攻击、防隐私、内容合规） | **事实与问责层**输出可信（逐数字核查、低置信拒答、留痕追责） |
| 湛江「粤海保」/ 湛江湾1号 | 给预警结论（"裸建议"） | 补上结论的可信度与责任链 |
| 湛江科技学院「智擎虾塘」 | 投喂执行闭环（硬件 + 塘口试点） | 不碰硬件与塘口，只做软件可信层 |
| 星环 Sophon / TI-ONE / Ragas / Evidently | 通用指标与平台 | 把指标翻译成养殖可解释的"错一次损失多少" |

### 2.4 问责场景表（立论的实证锚点）

| 误判类型 | 后果承担者 | 具体后果 |
|---|---|---|
| 投喂量建议偏高 | 养殖户 | 饲料浪费、残饵污染水质 |
| 病害用药建议错误 | 养殖户 | 药残 → 死鱼 / 被拒收 |
| 缺氧漏报 | 养殖户 | 翻塘，整塘损失 |
| 缺氧误报 | 保险公司 / 养殖户 | 定损争议 |

> ⚠️ **限制**：本表来自公开报道与常识推断。本项目**未做养殖户访谈**，
> 因此**不得**表述为"调研发现"。作为申报书论据前须由评审方（见 5.1）确认。

## 5. 表述红线（**本项目全文适用**）

### 5.1 三条否定性结论纪律

1. 禁用「均为 / 仅见 / 没有人 / 无人研究 / 完全空白 / 尚属空白 / 未检索到同类」；
   改用「**在所及范围内未见**」。
2. 否定性判断必须给出**举证范围与日期**，不得只写结论。
3. 「**未见披露 ≠ 不存在**」必须显式写出，尤其在提到稷安智算时。

### 5.2 数据模式标注（强制三选一）

每个数字/结论必须标注其模式：

| 标记 | 含义 |
|---|---|
| **【实测】** | 本项目自己跑出来的，可复现，原始数据在 `05-验证/` |
| **【合成】** | 由合成数据生成器产出，**不得表述为实测结论** |
| **【仿真】** | 仿真环境结果 |
| **【引用】** | 来自他人文献/报道，须给出来源 |
| **【自测·《蓝哨》】** | 来自上一轮项目自测，**非本项目实测、非第三方复现** |
| **【待核实】** | 未独立核实的二手材料 |

### 5.3 九条诚实性纪律

1. 数据模式标注（5.2）——**每个数字都要标**。
2. 核验状态标注——【已核实】/【子代理】/【待核实】。
3. 全称表述禁用（5.1）。
4. **未做的不得写成已做**。
5. **失败必须留痕**——失败实验、被淘汰方案一并保留。
6. 局限清单必须显式列出。
7. 修正记录公开（第 6 节）。
8. 无数据不产数——没有原始数据就不给结论。
9. 演示数据必须标明（合成数据不得伪装成真实塘口数据）。
